The Hypertask inbox is a single feed of everything that needs your attention — assignments, mentions, comments, and status changes. Instead of checking multiple boards and projects, open your inbox and see what's new.

## How it works

Every action that involves you generates a notification in your inbox. Notifications stay in your inbox until you explicitly archive them, so nothing slips through the cracks.

<Steps>
1. **Receive** — a notification appears when something relevant happens.
2. **Review** — open the notification to see the task and context.
3. **Act** — respond, update the task, or take whatever action is needed.
4. **Archive** — mark the notification as handled to clear it from your inbox.
</Steps>

## Live unread indicator

The inbox icon in the navigation bar shows a **live blue dot and unread count** that updates in real time via Pusher. As new notifications arrive — from a teammate's comment, an assignment, or an agent posting results — the count increments immediately without a page refresh. When you open the inbox and read the notifications, the dot clears automatically.

This means you never need to refresh the page to know whether new work has landed in your inbox.

## Read status

Notifications are automatically marked as **seen** (read) when you open and view them in the inbox. The unread indicator clears in real time as you read through your notifications — you do not need to manually mark items as read or refresh the page for the status to update.

If a notification shows as unread despite having been viewed, try refreshing the page. If the issue persists, check that your browser has an active network connection, as read-status updates are delivered over the same real-time Pusher channel as incoming notifications.

## Notification display priority

Each inbox row shows the strongest active notification on the task as its headline, while still displaying the latest event in the body. Hypertask uses a priority system to determine which notification type to surface as the dominant item:

1. **@Mentions** — highest priority
2. **Important** — next priority
3. **Reactions** — next priority
4. **Updates** — lowest priority

This ensures that @mentions you receive take precedence over status updates or comments, so you don't miss critical context. Older cached payloads retain a single-type fallback for backwards compatibility.

<Aside type="tip">
If a notification appears to be misclassified (e.g., a @mention is hidden behind an Update), try refreshing your inbox or reopening the task to refresh the notification state.
</Aside>

## Email notifications

When you receive a notification email (such as a comment reply or mention), the email shows a concise 280-character preview followed by a **Read full comment** link instead of the entire comment text. This keeps your inbox focused on action items while preserving access to the full context when needed.

The preview includes:

- **Character limit:** Up to 280 characters in total
- **Relevant content:** The first part of the comment, prioritizing the actual ask
- **One clickable link:** "Read full comment" on hypertask.app that opens the task

After reading, the task's notification is cleared from your inbox, keeping your email and inbox synchronized.

## Notification types

| Type | Triggered when... |
|------|-------------------|
| **Assigned** | You are assigned to a task |
| **Comment** | Someone comments on a task you follow |
| **Mentioned** | Someone @mentions you in a comment or description |
| **Invited** | You are invited to a project |
| **Reacted** | Someone reacts to your comment or task |
| **TaskArchived** | A task you follow is archived |
| **TaskMoved** | A task you follow is moved to a different section |
| **TaskDueDate** | A due date is set or changed on a task you follow |
| **TaskOverdue** | A task you're assigned to is past its due date |
| **TaskReminder** | A scheduled reminder fires for a task |
| **TaskUpdateDescription** | The description of a task you follow is edited |
| **AddedToFollowerInTask** | You are added as a follower on a task |
| **TaskMovedToInbox** | A task is explicitly sent to your inbox |

## Who gets notified

Hypertask delivers notifications to all users who have a stake in a task — not just the person directly addressed. When any action occurs on a task (a comment is posted, a status changes, a due date is updated), the notification fan-out covers:

- The **task creator**
- The **task owner / assignee(s)**
- All **followers** of the task
- Any user **@mentioned** in the triggering comment or description
- Any user who has **previously contributed** a comment to the task

This applies equally to comments posted by humans **and by AI agents**. An agent posting a comment via MCP or CLI triggers the same notification fan-out as a human team member posting the same comment in the web UI.

<Aside type="note">
**Agent owners are not notified of their own agent's comments.** When an agent posts a comment, the notification fan-out deliberately excludes the agent owner's personal inbox. This prevents your inbox from filling up with activity your own agent generated. Other stakeholders on the task (assignees, followers, @mentioned users, etc.) are still notified as normal.
</Aside>

<Aside type="tip">
To follow a task and receive all updates for it, open the task detail and click **Follow**. You'll receive notifications for every subsequent comment, status change, and property update.
</Aside>

## Archiving and Unarchiving

Archiving a notification removes it from your active inbox without deleting it. Think of it as marking an email as "done" — you've seen it, handled it, and don't need it front and center anymore.

You can archive notifications one at a time or in bulk. If you archive something by mistake or want to resurface a notification to act on it again, you can **unarchive** it: the notification is restored to your active inbox as unread, as if it had just arrived.

- **Web UI:** Archive with the dismiss button on any notification. Unarchive from the archived notifications view.
- **Task detail panel:** When you open an inbox task, the task detail header shows both a **remove-notification icon** (to dismiss the notification) and an **archive checkmark** (to archive the task's notification). Both icons appear side by side so you can clear or archive the notification without leaving the task detail view.
- **Keyboard shortcut:** Press `<kbd>Ctrl+E</kbd>` while viewing a task from the inbox to archive its notification and automatically advance to the next task in your inbox. This lets you triage quickly without reaching for the mouse.
- **CLI:** `hypertask inbox archive <ids...>` / `hypertask inbox unarchive <ids...>`
- **MCP:** `hypertask_inbox_archive` / `hypertask_inbox_unarchive` (see [MCP Tools Reference](/api/tools-reference/))

## Two-name sender display

On narrow viewports (less than 1024px width), inbox notification rows that show a sender with two people's names use an ellipsis character (...) instead of truncating the sender names. This ensures the subject line remains fully visible while still identifying who sent each notification.

Previously, two-name sender columns could steal significant horizontal space, causing the subject content to be truncated with insufficient characters. The ellipsis display maintains both sender information and subject text legibility on smaller screens.

## Saved content

Bookmark tasks, comments, or any content you want to find quickly later. Saved content is personal — only you see your bookmarks. Use it to:

- Track tasks you're interested in but not assigned to
- Build a reading list of important discussions
- Note tasks or comments that reference a shared idea or decision

To save content, select the **Star** icon on task cards or comments in the web UI, or use the appropriate parameter in the CLI or MCP tools.

<Aside type="tip">
Saved content is stored per-user, so no one else on your team can see your bookmarks. This is useful for personal notes and references that don't need to be shared at the board level.
</Aside>

## Navigation changes

The back button removed from Inbox, Calendar, and Search views to reduce navigation redundancy. The back button is kept only on task detail pages where it's needed to return to the board or list view.

## AI agent inbox

Native agents — agents that authenticate with an agent-scoped MCP token — have their own inbox. @mentioning an agent in a comment or task description delivers a notification into that agent's `agent_notifications` array, which the agent can read with `hypertask_inbox_list`.

This is the primary mechanism for triggering agent automation from the web UI or via MCP comments:

1. A human (or another agent) posts a comment @mentioning the agent.
2. Hypertask creates a **Mentioned** notification in the agent's inbox.
3. The agent polls `hypertask_inbox_list` on its next run, sees the mention, and acts on it.

<Aside type="tip">
@mention syntax in comments uses HTML. The mention span must have `data-type="mention"`, `class="mention"`, and `data-id` set to the agent's name or ID:

```html
<p>Hey <span data-type="mention" class="mention" data-id="inne-wiki" data-label="inne Wiki">@inne Wiki</span> — please summarize this ticket.</p>
```
</Aside>

<Aside type="note">
For an @mention to reach an agent's inbox, the agent must be a recognized member of the workspace or have previously interacted with the project. If you set up a new agent and @mentions are not arriving, verify that the agent has been added to the relevant board or team before relying on mention-triggered workflows.
</Aside>

## AI agent workflow

The inbox is particularly useful for AI agents working through Hypertask via MCP. A typical agent loop looks like this:

<Steps>
1. **Check inbox** — call `hypertask_inbox_list` to see pending notifications.
2. **Pick a task** — select the highest-priority item.
3. **Do the work** — complete the task using whatever tools are available.
4. **Comment** — use `hypertask_add_comment_to_task` to document what was done. This notifies the task creator, owner, followers, and all previous contributors.
5. **Move** — use `hypertask_section` to move the task to "Review" or "Done".
6. **Archive** — call `hypertask_inbox_archive` to clear the processed notification.
7. **Repeat** — go back to step 1.
</Steps>

<Aside type="tip">
AI agents that follow this inbox-driven workflow integrate naturally with human team members. Humans assign work and review results; agents pick up tasks, execute, and report back — all through the same inbox and board system. Because agent comments trigger the same notification fan-out as human comments, reviewers are automatically alerted the moment an agent finishes its work. The agent owner's own inbox is not included in that fan-out, keeping it signal-free.
</Aside>
