# Tasks

A task represents a unit of work that can be assigned, progressed, and tracked. It supports rich fields, priority levels, relationships, and subtasks.

## My Tasks

**My Tasks** is your personal task list across boards. By default it shows tasks assigned to you.

The list groups by due time: **Overdue**, **Today**, **This week**, **Later**, and **No due date**. Overdue stays at the top. Use **Group** to switch back to board groups. Saved My Tasks views remember the choice ([HTPR-6455](https://app.hypertask.ai/detail/project-15/6455)). Board split tabs still filter inside a time group.

### Scope in My Tasks

<span class="label label--brand">Improvement</span> The **Scope** button in My Tasks and the standard **Scope** command in <kbd>Ctrl+K</kbd> now open the same board picker list. The panel has been redesigned to match the board picker you use throughout the app, with search and standard keyboard navigation for quick filtering and selection. The previous, custom implementation has been replaced with the consistent board picker experience.

### Bulk selection and actions on My Tasks

You can select multiple tasks in the **My Tasks** view using the keyboard shortcut **G**, followed by **M**, to enter multi-select mode. This mirrors the selection behavior from the Kanban board for a consistent workflow.

Once in multi-select mode:

- **Verify your selection**: Each task you want to act on is checked. If viewing a filtered list, only tasks that are both checked and visible are included in the action.
- **Apply bulk actions**: The following actions are available at the bottom of the list:
  - Archive
  - Assign
  - Label
  - Move to column
  - Delete
- **Unselect**: Press **G** again or press **U** to exit multi-select mode.

Selected rows persist until you commit an action, so you can review the working set before bulk-actioning multiple tasks.

> **Tip**: The selection model matches the way you select tasks in Kanban, so if you're comfortable bulk-archiving or moving tasks on a board, the pattern transfers directly to My Tasks.

### Tasks you're snoozed on

To temporarily hide tasks from your My Tasks view, set a **snooze**. When you snooze until a date:

- The task no longer appears in My Tasks until that date passes
- The snooze date sets a calendar reminder so you can resurface the task later

A snooze is per task and independent of other views. Tasks remain otherwise accessible from boards, calendars, and saved views.

### Saved views

You can create and manage saved views on My Tasks to customize what you see. These views support:

- **Full filtering**: Filter by title, assignee, priority, due date, labels, and more. Filter options match the Kanban board filter menu, so you can use familiar screen-level controls directly on My Tasks.
- **Sorting**: Sort by any of the same fields, with priority as the primary sort key.
- **Board selection**: Show tasks from one board or across multiple boards.
- **Done columns hidden by default**: Done columns are hidden within each view to focus on active work.

Saved views persist at the account level and can be used as templates for board filter setups.

### How it works

When you toggle a filter, sort order, or board, your selection is saved with the view. The next time you open that view, the settings are applied automatically. You can create multiple views for example, one for active prioritized tasks, one for a specific project, or any combination that matches your workflow.

To create a saved view, open My Tasks and use the view toolbar to pick filters and sorting options, then select **Save view**. The view appears in the saved views list alongside system views like **Involvement** and **All tasks**.

### Excluding tasks you don't need

To hide distracting or temporary tasks:

- Use **View filters** to show or hide assignments, priorities, or tags that don't match your current focus.
- Create and pin a custom view with the exact criteria you want to see.
- Review tasks by tag or priority and archive or move them away when no longer relevant.

> **Note:** Saved views are scoped to the current team. Cross-board filters and sorting are supported, so you can see, for example, "all high-priority inbox tasks across all boards" in a single custom view.

### All Tasks view

The **All Tasks** view provides an at-a-glance overview of every active task across the board. It builds split views for each board section (To Do, In Progress, Done, etc.) from a single source of truth.

To access this view, navigate to the board and select **All Tasks** from the view toolbar.

### How All Tasks works

All Tasks uses a single fetch pass that loads rows once and builds board splits from those rows. As a result:

- Each board sees its own split of the task list.
- Quiet boards do not lose splits in favor of busy boards.
- The view is stable and deterministic across sessions.

### Drawing from multiple streams

Since All Tasks is board-wide, it aggregates tasks from all active columns and sections, making it useful for a quick health check or high-level tracking when you need to see everything that matters—not just what's pinned or currently in one section.

**Note:** Unlike **My Tasks** saved views, All Tasks does not automatically filter out onboarding, demo, template, and staging content, so those tasks may appear in the list. For visibility filtering, see [Board & Subtask Visibility](/features/board-visibility/).

### Search filters

When searching within a board or in saved views, you can now narrow results using search operators on fields:

- **from:** Restrict to tasks created by a specific user.
- **assignee:** Restrict to tasks assigned to a specific person.
- **in:** Restrict to tasks in a board, section, or column.
- **label:** Restrict to tasks with a specific label.
- **is:** Narrow by task type; for example, `is:card` to show only standard cards.
- **dates:** Show tasks with dates matching a condition (by default, **by due**), or filter by due date ranges.
  - `dates:2026-09-30` For tasks with that exact due date.
  - `dates:<2026-09-30` For tasks with a due date before.
  - `dates:>2026-09-30` For tasks with a due date after.
  - `dates:in-range 2026-09-01..2026-09-30` For tasks with a due date within the range.
  - `dates:overdue` For tasks marked overdue.
  - `dates:today` For tasks due today.
  - `dates:this-week` For tasks due within the current week.
  - `dates:later` For tasks due later than the current week.
  - `dates:todays` For tasks due on today and the day prior.
- **has:** Show tasks that have a value in a field; for example, `has:due-date` for tasks that have a due date (including empty values) or `has:assignee` for tasks that have someone assigned.
- Combining multiple operators is supported—for example, `from:alice label:urgent dates:>2026-09-30` to find urgent tasks created by Alice after a certain date.

To apply search filters:

1. Open **Kanban** or **Table View**.
2. On the board header (or in the saved view toolbar), select **Filter**.
3. Choose a field and an operator, then enter a value or pick from the options.
4. Repeat for additional filters to narrow the list.

Search filters apply at the board level in Kanban and in saved views. The available operators depend on the board's configuration.

### Chips in the search bar

<span class="label label--brand">New</span> The search bar includes:

- @ people picker: Start typing the @ symbol to select or create people.
- # board picker: Start typing # to select or create boards.

## My Tasks toolbar

<span class="label label--brand">Behavior change</span> The My Tasks toolbar now uses the same controls as the Kanban board: **Save view** and **Reset**. The previous separate Save button was removed while saving and resetting continue to work as before.

From the **Ctrl+K** command palette, you can still use **Save view as** to create a saved view, and **Reset view** to revert My Tasks to its default set of built-in filters. ## Creating a task

From a board or inbox, click **New task** (or use the keyboard shortcut **Ctrl+N** / **Cmd+N**). This opens the task creator with the following top-level sections:

- **Title**: The name or headline of the work.
- **Description**: Optional text explaining what to do.
- **Assignees**: One or more members to get notified and held accountable.
- **Sections & Columns**: Drag the task to a section or use the section picker dropdown.
- **Due date**: Pick a date or use predictive phrases like "tomorrow," "next week," or relative periods.
- **Priority**: Choose Low, Medium, or High.
- **Estimated time**: Optionally specify hours or a low-high range if needed.

Use **Write with AI** (**Ctrl+K** / **Cmd+K**, or the command palette) in the description area to turn a brief task idea into a fleshed-out task.

## OAuth connection flow

When Hypertask connects to a board from an external site or app, Hypertask now shows an **approve screen** first. The screen names the connector and the exact site that will receive access, letting you confirm before any access is granted.

This prevents a signed-in user from inadvertently granting external sites access to their entire board without prior approval.

## Editing a task

Open a task to view and edit all its fields. Unsupported columns or fields may be hidden based on your team's board configuration.

### Related fields

- **Assignees**: Current human assignees with ability to add or remove. Added assignees trigger notifications.
- **Workers**: Agent nodes and nodes can have their own assignee field, tracked separately from human assignees. Workers appear in the Relationships section under the *Workers* relation type.
- **Sections**: Drag tasks between sections to change their column. This can trigger auto-assign rules if configured.
- **Table view**: In Table view, you can also drag any row onto another section's card and the task moves into that section. The row is the drag handle, the section card is the drop target, and the change surfaces immediately in both views. (Note: this only works when no column sort is active; on /my-tasks, rows are grouped by time or board, so dragging doesn't target a section.)
- **Due date**: Click a date to pick another date or remove it. The date affects due date pickers and filter views.
- **Priority**: Change priority to reflect updated urgency.
- **Estimated time**: Type hours or a low-high range for time-tracking integration.

### Keyboard shortcuts

- **Ctrl+K** / **Cmd+K**: Open the command palette with AI-assisted task editing and Quick Actions.
- **Ctrl+N** / **Cmd+N**: Create a new task from anywhere on a board.
- **Ctrl+O** / **Cmd+O**: Open the link or auto-save picker when in a task detail view or comment.
- **Ctrl+J** / **Cmd+J**: Create a new task while opening the AI Task Writer for instant text generation.

## Task Reporter

With the **Task Reporter**, anyone on the task can update the task description directly. The Task Reporter indicator visually appears alongside comment headers, making it clear who has opened the description for editing just like comments.

### Permissions

- **Task Reporter** is available to any human assignee or worker on a task. The feature is not available for closed tasks.
- When you open the description in edit mode, you become the **Task Reporter** for that task.
- Only the Task Reporter can edit the task description. This prevents concurrent edits and restores the semantic meaning of "owner of the description field."
- If you close the description without saving any changes, the status clears and the next person to open it becomes the Task Reporter.

This model ensures a clear ownership of the description field, similar to comment ownership, which helps teams coordinate around tasks without stepping on each other's work.

Note: While you are the Task Reporter, you cannot switch to another task description edit until the current edit state closes, preserving a single active description edit at a time.

## Agent lease interactions

When you make manual changes to a task—"moving, assigning, unassigning, archiving, or deleting"—Hypertask cancels any active agent lease on that task and persists the change. Human modifications take priority over agent tasks, but agent-versus-agent collision protection remains in place. This ensures your task updates are never blocked by an agent while you're working.

## Task detail view

Open a task to see:

- Header with title, status section, assignees, workers, priority, and due date.
- Description area with optional attachments.
- Sections: Comments, Relations, Subtasks, Times, and Pages.
- Task Reporter indicator marking who can edit the description.
- **Top bar** with instant navigation and actions:
  - ← **Back to task** — Settings-style back button for navigation. On mobile, the back control matches the app's mobile back style with normal side spacing, making it easy to tap and fully visible up to 390px wide.
  - **Save** — Only right-aligned action remaining in the top bar; **Delete** is now moved to the Commands menu in the description or toolbar.

### Linked pull requests

Tasks can link to GitHub pull requests. The pull request section displays each linked PR with its status:

- **Open, Merged, Closed**: Show the current status as reported by GitHub.
- **Last observed**: The last-known status before the page loads.
- **Fetching...**: Indicates a background refresh is in progress.

<span class="label label--brand">Improvement</span> Tasks with linked PRs now show any saved PR status immediately—Open, Merged, or Closed—without waiting for GitHub to respond. Queries to GitHub run in parallel in the background and update the panel once the fetch completes, keeping the page fast and responsive. If you navigate away and come back, the PR panel refreshes again to stay current.

This change eliminates wait times for tasks with linked PRs and provides an instant-open experience even when GitHub fetches are slower than usual.

### Comments

The comment thread shows all comments on the task. By default, when you open a task with comments, the newest comment remains expanded so you can see the latest conversation.

<span class="label label--brand">Link handling</span> Plain web addresses in ticket descriptions and comments (http:// or https://) are automatically transformed into clickable links. Detects addresses based on recognized URL patterns, ensuring links in work notes and teammate discussions remain navigable on both desktop and mobile.

<span class="label label--brand">Performance improvement</span> When you open a task, comments now load once instead of twice. The initial SSR data used as the starting point, with React Query configured to skip a second fetch if the data is fresh. This eliminates redundant data handling and speeds up task loads: repeat visits are now approximately 0.6 seconds faster. New and edited comments still appear automatically without a reload, and realtime invalidation, reconnect reconciliation, and window-focus refresh continue to work as expected.

<span class="label label--brand">Improvement</span> Long task pages and comment threads now send their initial snapshot only once, reducing data copies and decoding passes. Repeat visit times drop from roughly 2.2 seconds to about 0.6 seconds. The change applies to tasks with many comments or long descriptions and focuses on the initial load speed, preserving all existing behavior for navigation, real-time updates, and comment handling.

### Actions

Common actions include:

- **Back**: Navigate back to the board using the ← Back to task button.
- **Move**: Relocate the task to a different section, board, or project.
- **Duplicate**: Create a copy with the same fields. When duplicating a task, the new task includes the full description and can be copied to another board in one step (see board-level Duplicate in the [Boards & Sections](https://docs.hypertask.ai/features/boards/) docs).
- **Archive**: Hide the task from current views while keeping it in the archive.
- **Delete**: Permanently remove the task. Delete is now available via the **Commands** menu in the task toolbar or description.

<span class="label label--brand">Undo for archive</span> When you archive a task, undo appears on the notification. Clicking **Undo** immediately restores the task to its original column without refreshing the page. The task stays restored after reloads and across archiving variants like archiving via the task menu or with the Ctrl+E keyboard shortcut.

## Relations between tasks

Create relationships between tasks to surface context without leaving tasks:

- **Block**: Mark a task as blocking another task.
- **Blocked by**: Identify what indirectly holds a task back.
- **Duplicate**: Link to other tasks that represent the same work item.
- **Workers**: Associate an agent or intelligent agent with the task for scheduling and coordination.

See a task's relations in the **Relations** section of the task detail view.

## Subtasks

Break down a task into smaller units. Subtasks appear in the task detail under the **Subtasks** section. Mark them complete to show progress toward the parent task.

## Task property rail

The task detail sidebar includes a rail of properties (title, priority, assignees, labels, etc.). The rail now occupies the full remaining dynamic viewport height, so it uses all available space rather than a fixed maximum and leaves no unused viewport space.

**Task properties no longer scroll with the task thread**, keeping them pinned to the sidebar for easy access while browsing comments and history.

When another browser, the CLI, or an agent changes a task, its open detail page refreshes the title, section, assignees, labels, priority, dates, status, attachments, and linked pull requests without a reload. If the live connection is unavailable, the page checks for changes every 10 seconds.

## Time tracking

Track work hours on tasks via the **Times** section:

- **B** opens the time entry modal from the task, or use the command palette ("Log time").
- Manual per-day rows let you log time for any calendar day without a timer.
- Export time logs as CSV for payroll or reporting.

See the [Time Tracking](https://docs.hypertask.ai/features/time-tracking/) guide for full details.

## AI Task Writer

The AI Task Writer is a prompt-based task creation flow that generates complete, shippable tickets from paste inputs.

### How it works today

The Task Writer writes tasks in your team's style. It uses board-aware prompts, pulls task templates from boards, and uses search to find related tickets instead of inventing them.

### Using the Task Writer

- From a board: **Ctrl+J** / **Cmd+J** and select **Create with AI** → **Task Writer**.
- From the command palette: **Ctrl+K** — search for "Task Write" and select it.
- From a task: Click the AI icon in the task header and select **Task Writer**.

After the Task Writer generates a draft, you can refine it just like any other AI-generated comment or description.

## Instant ticket opening

<span class="label label--brand">New</span> Tickets now load instantly from cached board data, with no spinner, no "Loading..." text, and no placeholder animation. The entire opening experience is fast and lag-free across desktop and mobile.

### What you see

- **Click to open**: When you tap or click a task, it appears in about 0.15 to 0.3 seconds on both desktop and mobile.
- **No loading animation**: No full-screen spinner, no pulsing grey bars, no brief placeholder state.
- **Suggested questions right away**: If the AI panel is open, suggested questions appear immediately—not waiting for the API response.

### Browser history

The browser back and forward buttons now behave consistently with the app:

- Press **Back** to return to the board. The board remains loaded and you can stay there.
- Press **Forward** to re-open the last ticket you viewed.

This lets you browse through tasks inside the app while the rest of your session stays tight and fast.

### Performance details

- Median open times are ~0.15 seconds on desktop and ~0.17 seconds on mobile.
- The first open after a board loads takes about 0.25 to 0.33 seconds; subsequent opens are closer to 0.13 to 0.18 seconds.
- The first open after a board loads now paints its cached title and description before expensive editing property controls, so the title and description appear instantly while controls like assignees, status, and priority stay warm. This tighter paint-first sequence reduces the first-open delta to about 0.10 seconds—considerably faster than before ([HTPR-6853](https://app.hypertask.ai/detail/project-15/6853)).

### Visual smoothness

<span class="label label--brand">Fix</span> Ticket pages no longer shift or jitter after opening. Visual elements that previously filled in after the initial paint now appear instantly as part of the cached board data, keeping the title, description, and controls in place across desktop and mobile for all test accounts ([HTPR-6899](https://app.hypertask.ai/detail/project-15/6899)).
