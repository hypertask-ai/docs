Hypertask billing controls license capacity, seat limits, and access tiers. Manage seats, track costs, and safely test billing changes in production without risking database side effects.

## Seats

Seats represent active users with individual access to Hypertask. Each seat corresponds to a user with login credentials and full access to the platform features.

**Seat limits by plan:**
- Free tier: No active seat limit
- Paid and team plans: Active seat limits per plan
- Enterprise: Custom seat limits

When you create or add accounts, new seats are allocated automatically. Upgrading your plan increases your seat capacity, unrestricted reassignments are tracked for billing reconciliation.

**View your forecast:**

## Testing billing changes safely

Stripe test-mode harness lets you safely test billing flows in production without risking database writes or production incidents.

The test harness:
- Runs **guarded seat billing logic** in a controlled environment
- Uses **in-memory application state** so tests don't affect live data
- Implements **bounded cleanup** to discard test states after execution
- **Never writes to the Hypertask database** during test runs

This means you can safely iterate on seat-loss logic, billing entitlement checks, and upgrade/downgrade flows in production-like conditions without creating cross-tenant leakage or corrupting live seats.

## Seat loss and automatic repair

Automatic repair of lost seats is available in production for affected teams. This feature prevents silent seat loss when users pool in from other teams, and helps maintain billing accuracy.

**How automatic repair works:**
- Detects when active teams have fewer seats than their current plan supports
- Verifies that the team has a valid Stripe payment method on file
- Requires billing-owner input if the active subscription cannot identify a single safe replacement Stripe item, to avoid modifying the wrong subscription item
- Blocks automatic repair and prompts for billing-owner review if:
  - A Stripe item is stored but no longer valid
  - The active subscription does not contain exactly one safe replacement at the stored price
  - Automatic selection could modify the wrong subscription item

Only teams with a payment method on file are eligible for automatic repair, and repair operations are guarded against unsafe mutations to subscriptions.

## License management

Seat allocation follows consistent rules across surfaces:

- New user creation adds a seat to your allocation
- Adding teammates in the app, via CLI, or through API all respect the same capacity checks
- Free-tier users may add teams and the first seat without restrictions
- Upgrading your plan increases your tracked capacity and adds seats automatically within the new tier bounds

## Team ownership verification

All billing-affected endpoints now verify team ownership server-side before performing mutations:

| Endpoint | Change |
|----------|--------|
| Checkout session creation | Verifies the authenticated user has billing access to the team before creating a checkout URL |
| Task mutations | Reads billing authority from the authenticated user and enforces access checks before state changes |
| Comment operations | Validates the requesting user's access to the target board and task before posting |

This prevents client-controlled parameter mismatches from bypassing authorization and ensures operations are scoped only to the intended team's resources.

## Stripe customer operations

Stripe customer creation for new accounts now surfaces all errors rather than silently swallowing them. Previously, certain paths returned null on failure without indicating the underlying issue, making debugging difficult. All customer creation paths now properly report errors to help you identify and resolve account or payment configuration problems.
