Connect a Slack workspace from Hypertask settings. Hypertask summarizes threads that mention a ticket, creates a ticket from a channel thread, and runs `/ht` as the linked person.

## What it does

**Thread summaries.** When a message in a channel the bot belongs to contains a ticket number such as `HTPR-123`, or a link like `app.hypertask.ai/detail/project-15/123`, Hypertask watches that thread. After the thread has been quiet for 30 minutes, it posts one comment on each matched ticket: a one-sentence outcome, two to four bullets for decisions and unresolved asks, who took part, and a link to the Slack thread. Later messages get another comment after the next 30 quiet minutes. Hypertask posts these summary comments.

**A ticket from a channel thread.** Mention `@Hypertask` in a channel and ask it to create, make, add, open, or write a task or ticket. `@Hypertask create a task for this` is the usual form. Hypertask reads the thread, writes a title and a short description from that conversation, files the ticket on the default project, and replies in the thread with the link. That thread stays watched, so later discussion is summarized onto the new ticket. A channel mention that asks to create a task uses this path and the default project. To choose the board, use `/ht create` with `--project`, or send a direct message.

**Commands and other messages.** `/ht` runs the commands below. A direct message, or a channel mention that is not a request to create a task, can ask in plain language to list, search, view, comment, assign, move, or update tickets, list projects or sections, add or remove a follower, or archive an inbox item. A direct message can also create a ticket and name the project.

`/ht` replies, and channel replies to those other mentions, are visible only to you. Direct messages appear in the conversation. The reply that creates a ticket from a thread is posted in that thread.

<Aside type="note">
Hypertask reads channels the bot has joined. In each channel, run `/invite @Hypertask`. Private channels work the same way.
</Aside>

## Setting it up

<Steps>

1. **Connect the workspace.** Open Settings, choose **Connect**, then **Slack**, and choose **Connect Slack**. Approve the request in Slack, in the same browser where you are signed in to Hypertask. One Slack workspace connects to one Hypertask team, and that team connects to one Slack workspace.

2. **Pick a default project.** Channel threads that become tickets are filed on this project. Until it is set, Hypertask asks the person who connected Slack to choose one under Settings → Connect → Slack.

3. **Invite the bot.** In each channel you want covered, run `/invite @Hypertask`.

4. **Link your account.** If your confirmed Slack email matches exactly one verified member of that Hypertask team, Hypertask links the accounts when you use the bot. Otherwise run `/ht connect`. Slack sends a link that expires in 10 minutes and works once. Open it while signed in as that Hypertask member, confirm, then return to the same Slack account and run the `/ht connect` command the page shows.

</Steps>

## Account linking

Slack actions that create or change work run as your Hypertask user, so they follow the access that account already has. When the Slack account is not linked yet, Hypertask asks for `/ht connect` before it applies the change.

`/ht disconnect` removes the current link. If automatic email matching still applies, a later Slack action links the same accounts again.

Summary comments stay with the integration. They are a record of the thread, separate from a comment you post yourself.

## Commands

| Command | What it does |
| --- | --- |
| `/ht help` | List the commands |
| `/ht connect` | Link this Slack account to your Hypertask account |
| `/ht disconnect` | Remove the current link |
| `/ht create <title> --project <name>` | Create a ticket on that project. Optional `--priority`, `--assign`, `--label`, `--section`, `--description` |
| `/ht search <text>` | Search tickets. Optional `--project` |
| `/ht list` | List tickets. Optional `--project`, `--status`, `--assignee`, `--section`, `--priority` |
| `/ht view <ticket>` | Show one ticket |
| `/ht comment <ticket> <text>` | Comment on a ticket |
| `/ht assign <ticket> <user>` | Assign a person. A Slack mention, `me`, an email, a display name, or a numeric user id works when it matches one project member |
| `/ht move <ticket> <section>` | Move a ticket to a section |
| `/ht update <ticket>` | Edit a ticket. Optional `--title`, `--priority`, `--status`, `--description` |
| `/ht inbox` | Show your notifications |
| `/ht projects` | List your projects |

## AI usage

Thread summaries, the draft written from a channel thread, and plain-language requests use your team's task-summary model and count toward that team's AI usage. Hypertask summarizes a thread after the thread mentions a ticket, or after a ticket is created from that thread.

## Permissions requested

Connect Slack asks for these bot permissions:

| Scope | Why |
| --- | --- |
| `app_mentions:read` | Receive `@Hypertask` mentions |
| `assistant:write` | Assistant conversations in Slack |
| `channels:history` | Read public-channel threads the bot has joined |
| `chat:write` | Post replies |
| `commands` | Provide `/ht` |
| `groups:history` | Read private-channel threads the bot has joined |
| `im:history` | Read direct messages |
| `team:read` | Identify the workspace during install |
| `users:read` | Show Slack names on summaries |
| `users:read.email` | Match a confirmed Slack email to one verified teammate |

## Disconnecting

Settings → Connect → Slack → **Disconnect** removes the workspace connection and stops watching. Comments already on tickets stay there. Removing the Hypertask app from Slack, or revoking its token, removes the connection as well.
