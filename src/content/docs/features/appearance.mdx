Your Appearance settings in Hypertask are now on a dedicated page, accessible from your main navigation or `Ctrl+K`. This page lets you control the visual look of the platform and configure default AI behaviors.

---

## Themes

Hypertask offers three theme options:

- **Light** — Clean, light interface for environments with ample natural light.
- **Dark** — Easy on the eyes in low-light or evening sessions.
- **System** — Automatically follows your device's night mode preferences.

To change your theme:

1. Open Profile → Appearance.
2. Select the desired theme from the Theme dropdown.
3. Refresh your view for full consistency across all boards.

<Aside type="info">
Dark mode is the default for new users and reduces eye strain during long work sessions.
</Aside>

---

## Task Page Preferences

From the Appearance tab, you can configure how tasks display:

- **Show task scroll** — When enabled, Hypertask automatically scrolls to fit the entire task description and comments when opening a task.
- **Subtask depth** — Adjust how many levels of subtasks are drawn as expanded by default.
- **Expand inline details** — Show fields like due date, assignee, labels, and attachments directly on task cards for quick scanning. Toggle off for a cleaner card view.

These settings apply to the task detail view and task editor across all boards.

---

## Keyboard Shortcuts

Jump directly to these settings from anywhere in the app:

| Shortcut | Action |
|----------|--------|
| `Ctrl+K` then type "Appearance" | Open Appearance settings page |
| `Ctrl+K` then type "Themes" | Jump to Theme dropdown |
| `Ctrl+K` then type "Settings" | Jump to task page preferences |

### Why These Settings Go on the Task Page

Task-related preferences like scroll behavior, subtask display, and inline details are now grouped on the **Task page** section of your Profile. This separates them from your personal identity information (General tab) and makes them easier to discover and configure.

## Team Default Models

You can select default AI models per team. Each team gets its own set of defaults, and the page shows "Defaults for <team>" to make the selection clear. Changes apply only to that team's context and do not affect others.

When no team-specific settings exist, options from an existing global default are used as the fallback. Once you define per-team defaults, they become the effective choice for that team's members.

This ensures customization without requiring global configuration changes.
