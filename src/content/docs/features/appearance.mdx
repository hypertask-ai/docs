## Themes

Choose from a range of visual themes to match your environment and preferences. All themes support light and dark modes, with a system default that follows your OS preferences.

### Available themes

| Theme | Best for |
|-------|----------|
| **Light** | Daytime work, clean aesthetic |
| **Dark** | Low-light environments, eye comfort |
| **System** | Follow your OS theme automatically |
| **AMOLED** | OLED/AMOLED displays, maximum contrast, true-black base |
| **Paper** | Warm editorial light aesthetic, paper-like feel |

### Activating a theme

Use the theme picker in the sidebar to switch themes, or search via the command palette:

- **Ctrl+K** Command palette (type **"Theme"**, select the theme)
- **Sidebar** - Go to Account settings, choose from the theme dropdown

AMOLED applies automatic color adjustments to surfaces previously rendered with dark grays, giving you a pure-black base and terminal-friendly input colors that pop on OLED screens. Paper is a warm, not-too-bright light theme suited for editorial workflows and reduced eye strain during extended sessions.

### Theme behavior

- Changes apply immediately across all boards and UI surfaces
- Theme preference is saved per user and synced across devices
- No configuration changes are lost when switching themes
- Common surfaces affected: card backgrounds, comment inputs, dropdowns, and modal overlays

<Aside type="tip">
AMOLED is automatically selected by default when your OS is set to "Dark mode" so that badge text remains readable on OLED screens. You can override this via the theme picker if you prefer a dark gray appearance on hybrid-display devices.
</Aside>

## Charts

Periodic charts (velocity, progress, and burnup) augment your boards as view-type pills and view-widgets. Chart view is not yet globally available everywhere, but you can toggle Charts on when Chart view is offered by your project or board context.

### Quick view-tabs pill bar

When Chart view is available, periodic charts appear as augmented pills in the view-tabs pill bar at the top of the board, alongside your Saved Views and standard views (Board, Calendar, Timeline). Clicking a chart pill opens Chart view for that period and chart type.

### Saved Views pill bar

For any Saved View that supports Chart view, the Chart pill appears in the saved-views pill bar. This gives you a persistent one-click path to Chart view after you open the board to that Saved View.

### Chart widget toggles

In boards or views where Chart view is offered, the Chart pill includes a small toggle icon inside it (e.g., <span style="font-size: 0.85em;">🚫</span> or <span style="font-size: 0.85em;">🚫</span>). Click the toggle to change between two chart styles:

| Toggle state | Available chart styles |
|--------------|------------------------|
| First (default) | Velocity chart — estimate-weighted completion per week |
| Second | Burnup chart — total completed vs total remaining over time |

For boards where Chart view is not offered, this toggle is not shown. Chart view options are surfaced by active boards in your workspace — contact your workspace owner to add Chart view to more areas.

<Aside type="tip">
When Chart view is available, you can use the Chart pill in either the view-tabs or saved-views pill bar to quickly jump to the chart view relevant to your current context.
</Aside>

## AI Models

Select AI models for specific features. Your choices show up as badges in the UI to make expectations clear.

<Tabs>
  <TabItem label="Per-feature" default>
    Assign models to specific AI capabilities:

    - **Task Writer** — model for generating task descriptions from prompts
    - **Summaries** — model for auto-summaries of comment threads
    - **Suggestions** — model for AI triage suggestions in the inbox

    Use per-feature settings when you want fine-grained control over where each provider excels. For example, use a quicker model for summaries and a more capable model for complex task generation.
  </TabItem>
  <TabItem label="Project-level" default>
    Projects can override the system-wide defaults with custom instructions and model choices that apply to all AI features in that project.
  </TabItem>
</Tabs>

### Default model selection

When you select **Auto**, Hypertask recommends a model based on your plan and enabled providers, prioritizing speed for summaries and suggestions, and capability for task generation. If you have multiple providers and models enabled, the fastest available model across them wins for performance-sensitive workflows.

### Bindings and overrides

- **Provider disables** — providers you turn off are never consulted, even if they're configured in your AI features settings
- **Model-tier badges** — some features highlight cost-effective or speed-optimized models with badges
- **Fine-grained overrides** — some features (e.g., task summary templates) can still pick faster models while others stick to more capable ones

<Aside type="tip">
If you're unsure, rely on the Auto assignment: it adapts to your plan's capabilities and provider setup without manual tuning.
</Aside>

## Admin configuration

Project owners and admins can configure default AI models at the system level. These settings appear in **Settings → AI → AI features**, where you can configure model mappings for key features that operate at the system level:

| Feature | Description |
|---------|-------------|
| **Task summaries** | Default model for auto-summaries of task comment threads |
| **Question suggestions** | Default model for intelligent suggestions in task triage and assignment |

Admin settings serve as a fallback for any project that doesn't have custom instructions. If a project has instructions or specific model preferences, those take precedence.
