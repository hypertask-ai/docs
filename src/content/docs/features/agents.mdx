Agents are autonomous workers that create, update, and manage tasks on your boards. They run as service accounts with scoped API keys and can act on their own behalf via bearer tokens.

## Create and configure agents

From the web UI:

1. Press **Ctrl+K**, open **Manage agents**, and select **New agent**.
2. Enter an agent name and description.
3. Choose a project and optionally limit the agent to specific boards.
4. Optionally enable **Team mode** by providing a provider billing API key to enable shared access. Agents default to **Private** mode.
5. Save the agent. Hypertask generates a scoped API key under the agent's profile.

Over MCP:

```json
{
  "action": "create_agent",
  "name": "Release Agent",
  "description": "Tracks and creates release tasks for HTPR-* tickets",
  "projectId": 15,
  "boards": [153, 155],
  "scopes": {
    "actions": ["hypertask_create_task", "hypertask_add_comment_to_task", "hypertask_link_tasks"],
    "memberships": {
      "projectId": 15,
      "boards": [153, 155]
    }
  }
}
```

Over REST API (`POST /api/agents`):

```json
{
  "name": "Release Agent",
  "description": "Tracks and creates release tasks for HTPR-* tickets",
  "projectId": 15,
  "boards": [153, 155]
}
```

The response contains the agent UUID and a token for authenticating the bearer token over MCP or HTTP.

If you open Agent Chat or list a team's agents and that team has none you can see, Hypertask adds a Hyper AI agent on a board of that team so the list is not empty. This also works when you can use the team but are not yet a member of a board.

## Agent status
Agent pages now show a single, consistent status across the agent detail page. When Hyper AI agents are targeted via chat, they reflect **On demand** rather than **Offline**, because Hypertask launches them on demand to handle your request instead of running as background workers that report a status.

<Aside type="tip">
Built-in Hyper AI agents are always **On demand** when you message them—their behavior changes from continuous background workers to on-demand launches. This means users won't see a persistent "Offline" status for these agents because they only appear when your conversation activates them.
</Aside>

## Agent Connected and First Task email messages
Agent notifications include mentions directed at agents (e.g., "Reply to @dev-bot"). These are handled with special guard-rules to prevent them from being incorrectly archived during snooze or reminder lookups. The system skips reminder validation when the notification is addressed to an agent, ensuring agent rows stay visible until you explicitly take action on them.

### Guest Hyper AI seeded notifications
Fresh guest inboxes now receive 4 seeded notifications from a Hyper AI agent. When available, the Important split is enabled, helping new users immediately experience AI-driven prioritization.

## Agent notifications
Agent notifications now use a shared onboarding email design for:
- **Your agent is connected** – Confirmation email when you sign up and connect an agent
- **Your first task** — Email when a task is assigned to your newly connected agent

These emails mirror your selected theme colors, typography, and layout tokens, so they match the look and feel of other in-boxed notifications. Subscribe to Agent notifications in your account settings or skip them entirely if you prefer list-only delivery.
