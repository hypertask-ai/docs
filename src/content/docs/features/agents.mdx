Agents let you attach an AI model to a workflow that can perform autonomous actions, such as reading tasks, writing comments, scheduling, or running utilities on the platform. They integrate with the Model Context Protocol (MCP) to surface tool calls, returning structured outputs that your agent can use to complete goals.

## How agents work

1. **Create an agent** â\x80\x94 Define a name, description, permissions, and open to task assignment.
2. **Connect MCP tools** â\x80\x94 Grant the agent access to tools like `get_tasks`, `create_task`, `write_comment`, and beyond.
3. **Orchestrate with workflows** â\x80\x94 Build a workflow using Ad-hoc triggers (e.g., task.assigned, comment.mention) or Scheduling Agents to run on a cron.
4. **Apply MCP credentials** â\x80\x94 Use BYOK or per-agent tokens so the agent can securely call tools.
5. **Start the agent** â\x80\x94 Toggle the agent "active" in its detail page; an external scheduler (GitHub Actions, Vercel cron, etc.) can start an agent on a schedule.

## Speed Engineer Git plumbing

The **Speed Engineer** agent can now bootstrap autonomous worktrees using Git plumbing from scratch. When the agent is configured as a Speed Engineer unit, it uses a Git helper probe to establish a fresh worktree, allowing it to work directly with repository sources in supported environments.

This capability is scoped exclusively to Speed Engineer instances; other agents retain the original atomic-file probe pattern and do not require Speed-only Git support.

## Worker ownership gate

To prevent conflicts when a managed agent attempts to work on a task, the worker verifies managed ownership before taking action. The agent verifies ownership before:
- Creating a writable worktree
- Posting a pickup
- Starting the coding provider

Transient lease conflicts remain queued with their exact error while other work continues. This prevents orphaned claims and ensures ownership remains consistent across agent interactions.

## List view and sorting

Browse and manage your agents on the Agents page (`/agents`). The view can be personalized in three ways:

| View type | How it behaves |
|-----------|----------------|
| **Grouped** | Boards are sorted by their most recent agent activity. Agents inside each board are sorted by their own newest activity. |
| **Flat** | All agents appear in a single list, sorted by latest activity. Open the margin ellipsis in the header to enable the flat view via `?group=0`. |
| **Production register** | A read-only reference for the current production environment, highlighting agents most recently active. |

Shortcuts: <kbd>Alt</kbd> + <kbd>1</kbd>â\x80\x94<kbd>9</kbd> quickly navigate to the first nine agents in the current view.

<Aside>
**Tip** â\x80\x94 Pin important agents to your synchronized views or use a saved view filter on assignees to focus on the team's active agents.
</Aside>

## Viewing specific agents

Click any agent to open its detail page. The detail page contains:

- **Basic configuration**
  - Name and description
  - Auto-assign toggles (boards, team, or project-wide)
  - MCP tools list and credential status
- **Activity and logs**
  - Recent task assignments and webhooks
  - History of tool calls signed by the agent
- **Actions**
  - Start/Stop agent toggle
  - Rename agent directly from the page
  - Configure webhooks and accessibility settings

### Live status and active task (HTPR-5417)

On the agents list and in agent detail pages, you can now see whether an agent is working and on what.

- **Status indicator** â\x80\x94 A pulsing dot next to the agent name shows it's actively holding a task lease. The dot stops spinning when the lease expires and re-asks for a new task.
- **Active task display** â\x80\x94 When working on a task, the card or detail page shows which ticket the agent is handling. The task name and key details are visible so you can track which agent is working on what.
- **Manage agent** â\x80\x94 From the list, you can archive or delete agents you no longer need. Use the inline actions (three-dot menu or dedicated buttons) to remove or archive a single agent without affecting other agents.

This visibility helps you spot resource-heavy agents, see which tickets are being processed, and clean up unused agents.

### Hovering over agents ([HTPR-5605])

Entering the hover state on an agent card opens its detail page. This provides a quick, keyboard-friendly way to see an agent's current state, recent activity, and quick actions without fully opening its page. This behavior applies to both list and detail views.

### Renaming agents

You can rename an agent directly from its detail page:

1. Click **Agents** in the sidebar.
2. Find the agent and open its page.
3. Click in the visible **title field** â\x80\x94 the field is borderless and editable in place.
4. Type a new name, then press <kbd>Enter</kbd> to save.
   - <kbd>Escape</kbd> cancels the rename without changing the URL.
   - Clicking away or blurring the field saves the new name.
5. The URL automatically updates to match, so an agent previously at `/agents/drainer-1` will become `/agents/new-name`.

<Aside>
Renaming an agent does not reset its MCP credentials or task assignments; it only updates the accessible slug and bookmarks.
</Aside>

## Agent webhooks

Wake an agent the moment it is mentioned or assigned by registering webhooks:

| Property | Description |
|----------|-------------|
| **Event type** | `<code>comment.mention</code>` or `<code>task.assigned</code>` |
| **Deliveries** | HTTPS POST to your configured endpoint with signed body and ID |
| **Board filtering** | Optional scope to a single board if you only want notifications on that scope |

Webhooks make agents reactive to incoming mentions or task assignments, supporting faster triage and asynchronous execution.

## Scheduling agents

Run an agent on a schedule using an external scheduler:

<Tabs>
<TabItem value="github-actions" label="GitHub Actions">

1. Create a GitHub Actions workflow that toggles "active" for your agent via the MCP credential or internal API.
2. Set your cron schedule in the workflow file.
3. The agent respects its MCP tools, board permissions, and credential encryption.

```yaml
name: Schedule Drainer-1
on:
  schedule:
    - cron: "0 * * * *"  # Hourly
jobs:
  awake-agent:
    runs-on: ubuntu-latest
    steps:
      - run: |
          curl -X POST https://app.hypertask.ai/internal/schedule \
            -H "Authorization: Bearer ${{ MY_TOKEN }}" \
            -d '{"agentId":"drainer-1","active":true}'
```

</TabItem>
<TabItem value="vercel-cron" label="Vercel Cron">

1. Add a cron job function in your Vercel project.
2. Call the agent toggle endpoint with your service token.
3. Ensure the endpoint validates and encrypts tool calls.

```js
export const config = {
  schedule: {
    cron: "0 * * * *"  // hourly
  }
}

export default async function handler() {
  await fetch('https://app.hypertask.ai/internal/schedule', {
    method: 'POST',
    headers: { 'Authorization': `Bearer ${process.env.HT_AGENT_TOKEN}` },
    body: JSON.stringify({ agentId: "drainer-1", active: true })
  })
}
```

</TabItem>
</Tabs>

<Aside>
When using a scheduler, consider the agent's rate limits, MCP token lifecycle, and error handling to avoid loops or uncontrolled executions.
</Aside>

## MCP tools

MCP tools are the building blocks an agent can call to interact with Hypertask. The agent server surface exposes tools for tasks, comments, board operations, time tracking, and configuration.

Example MCP tool invocation:

```json
{
  "tool": "get_tasks",
  "args": {
    "boardId": "board-123",
    "assignee": "bot-456",
    "limit": 50
  }
}
```

See the [MCP Tools Reference](/api/tools-reference) for the complete schema list.

## Getting started

<Tabs>
<TabItem value="quick-create" label="Quick create">
1. Go to **Agents** (`/agents`).
2. Click **New agent**.
3. Name it and provide a short description.
4. Select boards or projects where it may be auto-assigned.
5. Toggle it **active** and optionally set a webhook or job token.
6. Its MCP tools become available to any scheduled or ad-hoc workflow.
</TabItem>
<TabItem value="import" label="Import from MCP">
1. Open the agent's detail page.
2. Under "MCP tools," click **Import tools**.
3. Choose a provider or import by tool list and signatures.
4. Save credentials and start the agent.
</TabItem>
</Tabs>

<Aside>
Many teams build agents around a recurring pattern â\x80\x94 e.g., a "drainer" agent for stale tasks, a "bot" for support triage, or a "replier" for common questions. Reuse saved workflows as a blueprint when creating new agents.
</Aside>
