Agents in Hypertask are autonomous AI entities that can create, update, or delete tasks, leave comments, and execute long-running workflows. They are connected to Hypertask via the Model Context Protocol (MCP) or triggered from the UI.

## Quick setup

1. Go to any board and open the AI pane.
2. Click **Create agent** and give the agent a name and description.
3. Choose a base model and attach an agent token (see “Agent tokens” below).
4. Save — the agent is ready to create tasks, leave comments, or join workflows.

## Agent tokens

Securely connect your agent to Hypertask using a dedicated token. Tokens grant the agent scoped access and can be rotated or revoked at any time.

### Create and manage tokens

From the AI pane:

- **Create token** → generates a fresh, encrypted token tied to the agent.
- **Rotate token** → revokes the old token and creates a new one.
- **Revoke token** → denies the agent’s access to Hypertask.

Tokens inherit the agent’s board and permission scope at creation time. Revoke a token to force the agent to exit any in-flight workflows and to stop all API access.

## Agent workflows

Add agents to step-based workflows using the MCP agent team infrastructure. Each step can invoke a different tool, inspect intermediate results, and transact changes to tasks or comments.

### Step types

- **Tool call** – invoke an MCP tool when the condition matches.
- **Condition check** – branch based on task labels, priority, or custom fields.
- **Delay** – pause for a configured duration before the next step.
- **Loop** – iterate over a set of tasks or comments until a condition clears.

```json
  "enabled": true,
  "steps": [
    {
      "type": "Tool call",
      "name": "List tasks",
      "config": {
        "endpoint": "/mcp/tasks/search",
        "query": {
          "labels_in": ["bug"],
          "board_id": "<BOARD_ID>"
        }
      }
    },
    {
      "type": "Tool call",
      "name": "Set priority",
      "config": {
        "endpoint": "/mcp/tasks/update",
        "payload": {
          "ticket_number": "{{ $task.ticket_number }}",
          "priority": "high"
        }
      }
    }
  ]
}
```

You can reference any `$task` from the previous step using Jinja syntax.

## Scheduled vs ad-hoc

- **Ad-hoc agents** react to events (e.g., agents that assign new tasks from custom schedules or templates).
- **Scheduled agents** are run periodically via external schedulers (GitHub Actions, crontab, Cloudflare Workers, Vercel cron). Run the CLI to schedule a background operator:

```bash
hypertask agent schedule:run \
  --agent-name "weekly-board-balance" \
  --schedule "0 2 * * *" \
  --board-id <BOARD_ID>
```

See [Scheduling Agents](./scheduling.mdx) for more on recurring workflows.

## Security and privacy

Agents operate under the same authentication and permissions model as your account. Restrict board access and agent tools to the minimum required scope. Rotate tokens regularly and monitor agent activity in the AI pane.

For board-level security or data isolation policies, see [Board Visibility](./board-visibility.mdx) and [Observability & Error Tracking](./observability.mdx).

## Troubleshooting

<Aside type="note">

Check the AI pane for error messages when agents fail. Common causes include missing tokens, out-of-scope boards, or permission mismatches.

</Aside>

- **Agent fails to create tasks** – verify the MCP token is active and the agent schedule has board access.
- **Tools return 403 Forbidden** – the agent’s token lacks the required write permissions on the Board or Team.
- **Agent timeouts** – reduce the number of tasks processed in a single workflow step or increase timeouts in the schedule configuration.
