The **Hypertask AI assistant** lives at your fingertips. Use it to create tasks, enhance descriptions, draft code, summarize threads, or prescribe actions throughout your workflow.

## AI Task Writer and Write with AI
### Create tasks from prompts

The AI Task Writer instantly turns text into structured tasks. Just ask in natural language, and the assistant fills in title, description, due date, and assignee if you include that context.

```bash
# CLI: Create a task with a rich description
ht task create "Design the upcoming Q3 marketing campaign. Include three concepts: social-first carousel posts, short-form video ideas for TikTok and Instagram Reels, and a longer-form blog about Q2 performance. Target HQ team. Due next Friday from HQ."
```

In the UI, use the AI Task Writer from the New Task flow. The editor is context-aware: it respects the board, team, and board-level AI instructions you've configured.

When a ticket already has a title or description, opening Task Writer starts the draft immediately. It uses the title, description, tags, priority, and size as context. Empty tickets still open with the prompt, and your original wording remains available for follow-up edits.

### Automatic draft drafts behind owner-specific flag

By default, AI Task Writer generates automatic draft descriptions in the task creator. These drafts respect board-level style rules. To control who sees automatic drafts, owners can enable a per-user feature flag:

**For owners**, automatic drafts are enabled and visible in the New Task flow. The system generates clear, concise drafts based on the prompt and your task instructions.

**For non-owners**, automatic drafts are not rendered. The AI Task Writer opens with a blank prompt so you can compose from scratch or paste an existing description.

This flag toggles behavior server-side and in the UI, and a corresponding setting in your profile hides the feature toggle entirely for your account. Manual task writers remain fully functional for all users.

```bash
# CLI: Create a task; AI will generate a draft if enabled for your account
ht task create "Design homepage overlay component with glassmorphism"
```

### Write with AI in comments and descriptions

Start a comment or task description with **/ai** to open the AI Task Writer.

- **/ai** — Generate a draft for the active text field.
- **/ai rewrite** — Improve or rethink what you typed.
- **/ai fix** — Correct grammar, sharpen tone, or expand with details.

The assistant drafts directly into the field, ready for your review.

### Preserve screenshot references

The AI Task Writer now preserves screenshot file links pasted into your draft. The assistant recognizes screenshot URLs and keeps them clickable after saving and reloading, without converting them into `HT_MEDIA` placeholders.

### Start a fresh AI chat session on unopened tickets

When you open the AI chat panel on a task that hasn't been visited before, the assistant starts with a clean slate. The system ignores any existing chat history from previous tickets and begins a fresh conversation, so each unopened ticket gets its own independent chat session.

<Aside type="tip">
This separation prevents context from bleeding between unrelated tasks and keeps each chat focused on the work at hand.
</Aside>

### ChatProvider and hooks

When using AI chat features on server-rendered routes like task detail pages, ensure the UI is rendered within the `ChatProvider` boundary. This prevents hydration errors and ensures proper context control for hooks like `useAiChatContext`.

This is automatically handled for standard flows — use the AI Task Writer, context menus, and panel-based chat — and is handled by the fallback behavior on detail pages that load the provider safely.

## Agent Chat interactions

Agent Chat use cases rely on several native behaviors: running in multiple views, handling long-running turns, stopping work in progress, and agents proposing tickets. Model selection is chosen by the agent's engine (Claude or Codex) and should not be overridden by the chat lane.

### Model selection per engine

Agent Chat respects the engine configured on an agent when selecting a model:

- **Claude-based agents** use Claude models (for example, claude-sonnet-5). The chat lane does not inject Codex-style model names or IDs for Claude agents.
- **Codex-based agents** use Codex models (for example, gpt-5.6-luna). The chat lane does not inject Claude-style model names for Codex agents.

If an agent's engine and model match during configuration, Agent Chat uses that pairing directly. Mismatches in model naming between the configuration and runtime (for example, legacy Codex-style names on Claude engines) are resolved server-side; chat must operationalize the correct model per engine.

<Aside type="tip">
Chat lane configuration must align with the agent's engine. Changes to engine/model requirements should be made in the agent's settings first, then propagated to the chat lane to avoid operational conflicts.
</Aside>

### Concurrent Agent Chat sessions

Multiple agents can interact with a user in separate, independent chat panels. Each agent keeps track of its own thread and history within the context of the relationship.

### Restarting a hung turn

When an Agent Chat turn fails to finish within the timeout window, the thread restarts automatically. The new turn uses fresh context for the current agent, and the user can continue the conversation from scratch.

<Aside type="note">
This recovery replaces the previously convoluted flow for stuck threads. You no longer need to page refresh to resume work.
</Aside>

### Stop work during an active turn

While an Agent Chat turn is in progress, the working indicator displays a **Stop** button. Click it to cancel the current run and return the thread to a stable state where you can send a new message.

### Agents proposing tickets

Agents can propose specific tickets rather than only talking about work. The proposal appears as a card in chat, targeting board and column contexts atomically with the proposal:

```text
[Propose] Create "ACME Output Report v2" in Priority / Work

The model intends to draft this report immediately.
Do you want to accept this proposal and proceed?
```

- The proposal card shows a short description and correct board/column references for your own environment.
- Accepting the proposal creates the ticket and immediately shifts you to a comment mode where you can confirm or refine the draft.
- This tightens the round-trip from suggestion to action, eliminating ambiguity about where the new ticket should live.
- The proposal is accessible via the `chat.propose` MCP tool when needed in agent workflows.

<Aside type="tip">
If a proposal doesn't match intent, simply decline it. The thread moves forward without creating output that doesn't fit current needs.
</Aside>
