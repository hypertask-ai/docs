We treat HEIC and HEIF images like any other file: they render consistently across thumbnails, inline previews, galleries, and lightbox views. If a preview isn't suitable, exclude the format from previews or use a low-res fallback.

## Supported formats

| Format | Default behavior |
|--------|------------------|
| HEIC/HEIF | Keep the original for download; the system generates a JPEG copy for previews |
| JPEG/PNG/WebP | Render at full quality |

## Viewing HEIC/HEIF

1. Attach a photo from an iPhone or Mac.
2. The platform creates a browser-compatible JPEG copy for previews, while the original HEIC/HEIF is preserved for download.
3. See it in the same places as regular images:
   - **Attachment thumbnails** below comments and email bubbles
   - **Inline embed** inside a comment or task description
   - **Board gallery** or gallery views that show attachments
   - **Task detail lightbox** with a thumbnail strip at the bottom

## Downloading HEIC/HEIF

HEIC and HEIF photos uploaded to tasks and comments retain their original file format in the download. When you click **Download** on an attachment:
- The original HEIC/HEIF file is downloaded, preserving the full image quality
- Previews across the platform use the generated JPEG copy for faster rendering and broader compatibility

This ensures you can access the highest-quality version of your photos while maintaining fast, consistent previews everywhere else.

## Excluding previews

To prevent HEIC/HEIF from generating previews (e.g., if the file is too large for preview generation):

1. Open the attachment's context menu (three dots).
2. Select **Excluded from previews** to disable automatic preview generation.
3. Uploaders still receive the file; observers only see the original format and a download link.

## Lightbox image strip

In the task detail lightbox, the thumbnail strip shows all attachments in that task. Supported formats and non-preview status appear consistently across all attachments.

## Handling malformed previews in the lightbox strip

If the lightbox shows a broken image icon for a non-decodable file:

- A file icon now appears instead of a broken icon, making it clear the image content could not be decoded.

## Warnings for unexpected content

If a file exhibits preview or display issues (broken icons, no thumbnail, or an unexpected format shown), check:
- The file is flagged as excluded from previews (if the goal was to prevent preview).
- The file is a HEIC/HEIF image under preview logic (historically, some browsers rendered these as named files before conversion completed).

## Upload tips

- **Keep resolution manageable:** Very large HEIC images can lead to longer preview conversion times.
- **Review lightbox strip:** If a thumbnail seems wrong after a HEIC upload, the browser might still be loading a placeholder until conversion finishes.

## Paste support

You can paste photos directly into comments and task descriptions. The system handles both HEIC/HEIF files and regular image formats in the same paste handler:
- HEIC/HEIF: Preserves the original and generates a JPEG preview
- JPEG/PNG/WebP: Downloads as-is

This gives you a single paste workflow whether you're uploading from Photos via copy-paste or dragging and dropping files.

## Handling blocked image hosts

<span class="label label--brand">New</span> If your network or a firewall blocks the image server domain, attachments now retry through the app domain and display instead of staying broken.

### How it works

- Images usually load directly from `files.hypertask.app`.
- When a request to `files.hypertask.app` fails (for example, due to network restrictions or a firewall), the app retries once through `app.hypertask.ai`.
- On successful retry, the image displays in comments, task descriptions, attachments, and the task detail lightbox.
- This happens automatically; no configuration is required on your side.
- Normal networks that can reach `files.hypertask.app` continue to load images straight from the image server, so performance is unchanged.

### When this helps

This change helps users on restrictive networks (including some corporate Wi‑Fi and VPNs) where:
- The image host is blocked, resulting in broken images or connection errors.
- You cannot easily unblock the domain.
- You don't have control over network policy.

Example scenario: A comment includes an image attachment, but your network blocks `files.hypertask.app`. Previously the image would appear broken. Now the app retries through `app.hypertask.ai`, and the image loads as expected.

### Reloading for browsers that blocked images before

If you saw broken images on a previous visit and still use a network that blocks the image server:

- <strong>Refresh the ticket page</strong> and the attachments with retry behavior will load properly.
- After the initial load, the images are cached by your browser, so you should not need to re-enter restrictive network conditions to see them.
