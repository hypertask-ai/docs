## Board access, invites, and permissions

### Board invites and access
<span class="label label--brand">Security fix</span> Sharing access to a board now respects team boundaries. A board invite:

- Only adds the signed-in person to the board that generated the invite.
- Is refused when no login is provided.
- Is refused if the invite target board differs from the invite source board.
- Can only be resended by the board's owner and current members.

**Behavior before this fix:** An invite could be successfully resent and used to create tickets on a different board, potentially exposing cross-team data.**\\n\\n**After this fix:** Each board's access is gated strictly. Invites can only be resent and used within their intended context. Users outside the board's membership cannot leverage invites to access or create tickets on other boards.

This change ensures invites are a scoped, safe method to grant board-level access without exposing cross-team boundaries.

### Adding columns and sections
<span class="label label--brand">Security fix</span> Adding columns to a board is now restricted to board members only. A signed-in person who is not a member of the board's membership will be refused when attempting to add a column.

**Behavior before this fix:** An unauthorized user could add columns to a board they were not part of, potentially affecting multiple team areas.**\\n\\n**After this fix:** Only board members (including board owners, members, and invited participants with valid access) can add columns. This restriction aligns with the board-wide access model and ensures that board structure changes are controlled within the intended team context.

### "Board unavailable" error screen handling
<span class="label label--brand">Fix</span> The "Return to previous board" button now safely handles the "This board or ticket is unavailable" error screen.

**Before this fix:** Clicking the "Return to previous board" button while encountering an unavailable board would trigger an immediate server request that caused the browser to crash.**\\n\\n**After this fix:** The button gracefully handles the unavailable state without crashing. Users can safely return to their previous board or navigate to another area of Hypertask without encountering errors.

## Creating a board

## Quick add with N or Shift+C

Use quick add when you only need a task title. It works in both board and table views.

1. Open your board. Focus a column or select a task in the column where you want to add work.
2. Press **N** or **Shift+C**. A small title box opens in that column. If nothing is selected, it opens in the first column. In table view, it uses the selected row's section or the first section.
3. Type a title and press **Enter** to create the task.
4. Press **Escape** to close the box without creating another task.

You can also open quick add with a column's **+** button. Press **C** without Shift to open the full task editor instead.

The shortcuts do not run while you are typing in a field or while a dialog or command palette is open.
## Select cards on your phone

On a phone, hold a card for about a second and let go without moving your finger. The card gets a tick and the selection bar opens at the bottom, with archive, assign, labels, move and more actions.

- While cards are selected, tap another card to add it, or tap a ticked card to remove it.
- Hold a card and drag it to move it, as before. Dragging never selects a card.
- When no card is selected, a tap opens the card as usual.
