## Board access, invites, and permissions

### Board invites and access
<span class="label label--brand">Security fix</span> Sharing access to a board now respects team boundaries. A board invite:

- Only adds the signed-in person to the board that generated the invite.
- Is refused when no login is provided.
- Is refused if the invite target board differs from the invite source board.
- Can only be resended by the board's owner and current members.

**Behavior before this fix:** An invite could be successfully resent and used to create tickets on a different board, potentially exposing cross-team data.**\n\n**After this fix:** Each board’s access is gated strictly. Invites can only be resent and used within their intended context. Users outside the board’s membership cannot leverage invites to access or create tickets on other boards. ([HTPR-7162](https://app.hypertask.ai/detail/project-15/7162), [HTPR-7176](https://app.hypertask.ai/detail/project-15/7176)).

This change ensures invites are a scoped, safe method to grant board-level access without exposing cross-team boundaries.

### Adding columns and sections
<span class="label label--brand">Security fix</span> Adding columns to a board is now restricted to board members only. A signed-in person who is not a member of the board's membership will be refused when attempting to add a column.

**Behavior before this fix:** An unauthorized user could add columns to a board they were not part of, potentially affecting multiple team areas.**\n\n**After this fix:** Only board members (including board owners, members, and invited participants with valid access) can add columns. This restriction aligns with the board-wide access model and ensures that board structure changes are controlled within the intended team context. ([HTPR-7165](https://app.hypertask.ai/detail/project-15/7165)).
