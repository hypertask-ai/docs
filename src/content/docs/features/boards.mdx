Every project in Hypertask has a **board** — a visual workspace where tasks flow through customizable columns called **sections**. If you've used Kanban boards before, this will feel familiar. If you haven't, think of it as a whiteboard with columns that represent stages of work.

## Authentication

Hypertask supports multiple authentication methods, all integrated through the server-side session layer:

### Email-based authentication

- Sign-in with a six-digit code delivered via email
- Access a persistent sign-in link (doesn't expire until used)
- No need to manage custom tokens — the session is handled server-side
- Reliable across mail scanners and email clients

### Sign-out

All authentication flows support clean sign-out that immediately invalidates the session and clears cookies.

## Board Management

Hypertask provides direct actions to archive and delete boards through the **Ctrl+K** command palette.

### Archive a board

To temporarily remove a board from your workspace:

1. Press **Ctrl+K** to open the command palette
2. Search for **"Archive"** and select the board you want to archive
3. Confirm the action in the palette-styled modal

Archived boards are hidden from the main board list but preserved in the **Archive** section. You can unarchive them at any time using the same Ctrl+K.

### Delete a board

To permanently remove a board:

1. Press **Ctrl+K** to open the command palette
2. Search for **"Delete"** and select the board you want to delete
3. Type the board name to confirm in the modal that appears (required for safety)
4. Click **Delete** to remove the board and all its tasks permanently

Deleted boards cannot be recovered. This action permanently deletes all tasks, comments, labels, and customizations on the board, so use it with caution.

### First-board redirect

When you first create your first board using Ctrl+K, the command palette will redirect you directly to that new board for immediate use. After your first board, the redirect behavior applies when creating additional boards — you'll be taken to the newly created board automatically.

## Sidebar

The sidebar groups your workspace navigation and project controls into a consistent layout. Use the account section in the sidebar to manage your config:

- **Theme picker** — switch between Light, Dark, System, AMOLED, and Paper theme (Light, Dark, System, AMOLED, and the new Paper warm editorial light theme)
- **Team switcher** — quickly switch between workspaces or projects
- **Account chevron** — manage your account settings and preferences

<Aside type="tip">
Press <kbd>Ctrl+K</kbd> to open the command palette and quickly access board sorting toggles and view management.
</Aside>

### Sidebar overlay sidebars

At half-screen viewports (typically 1024px width), overlay sidebars for Settings and Calendar boards/filters use fixed widths for better space management:

| Sidebar type | Width at half-screen |

These widths are applied via Tailwind's `sm:` breakpoint, providing consistent layout behavior regardless of viewport size. All content within these sidebars is fully accessible and scrollable within the fixed width.

### Browser tab title

The browser tab now displays your board name in a clear, scannable format:

- **Board name first** — Your board appears before the application name (e.g., "ine • Hypertask (board name)")
- **Bullet separator** — Uses a subtle bullet (•) to separate board and app names
- **No prefix or repetition** — No Hypertask prefix or repeated name
- **Dynamic on board switch** — Updates automatically when you switch to a different board

This change improves clarity in tab managers and on task-switching workflows.

## Archive View

The Archive section shows tasks and boards that have been archived. The Archive view defaults to showing only active boards to reduce visual noise. Hidden archived boards are not shown unless you invoke them explicitly.

To access archived boards:

- **Ctrl+K command palette** — search for "archived" to access archived board items
- **Keyboard** press <kbd>Ctrl+K</kbd> and select the archived view option

On narrow viewports (below `< 1024px`), the Archive section uses the full available width, giving you more space to read and interact with archived content.

### Archived Boards

- By default, archived boards appear hidden in the Archive view — only active boards are displayed initially
- Archived boards can be accessed via the Ctrl+K command palette when you need to review or restore them
- The view optimizes space so you focus on currently relevant boards

### Viewing Archived Tasks

- Tasks are listed with their associated board and section
- Archive status is clearly indicated on each item
- You can unarchive items to restore them to their original section

## Sections

Sections are the columns on your board. New projects start with three defaults:

- **Todo** — work that needs to be done
- **Doing** — work in progress
- **Done** — completed work

These defaults are just a starting point. You can rename them, reorder them, add new ones, or remove them entirely. Common setups include:

| Workflow | Sections |
|----------|----------|
| Simple | Todo, Doing, Done |
| Development | Backlog, Todo, In Progress, Review, Done |
| Content | Ideas, Drafting, Editing, Published |
| Support | New, Triaging, In Progress, Waiting, Resolved |

### Customizing sections

Each section supports the following configuration:

- **Name** — the column label displayed on the board
- **Visibility** — show or hide sections without deleting them (hidden sections retain their tasks)
- **Ranking** — drag sections to reorder them, or set a rank value directly

<Aside type="tip">
Hiding a section is useful when you want to temporarily declutter the board without losing any task data. Tasks in hidden sections still appear in search results and saved views.
</Aside>

### Hiding columns

You can hide sections that currently contain no tasks to reduce visual noise. This applies to both empty columns and regular columns that you want to keep but don’t need to see all the time.

To hide a column, use the **Ctrl+K** command palette:

1. Press **Ctrl+K** to open the command palette
2. Search for **"Hide"** to find column-hide actions (Ctrl+K “Hide column” hides the current section and closes the palette)
3. Select the column to hide it immediately
4. Search for **"Show"** to re-enable hidden columns (Ctrl+K “Show columns” resurfacing hidden sections)

<Aside type="tip">
Hiding a column is a UI toggle that persists per user — other team members will see the column as visible if their own filter/configuration differs.
</Aside>

### Hiding empty columns

You can hide columns that currently contain no tasks to reduce visual noise. There are two ways to toggle this:

- **Ctrl+K** — open the command palette, search for "empty", and select **Show empty columns** or **Hide empty columns**. The command label updates to reflect the current state.
- **Manage Columns modal** — use the visibility toggle for each individual section.

Both controls flip the same board-level setting, so changes made in one place are immediately reflected in the other.

### Sorting sections

By default, sections appear in alphabetical order. Customize your board layout with the following options:

| Control | Description |
|---------|-------------|
| **Segmented mouse-only toggle** | Choose between **Teams** and **Recent** sections with a mouse-optimized segmented toggle below the search bar |
| **Keyboard shortcut** | <kbd>Ctrl+K</kbd> — search for "sort" to open board sorting options |
| **Drag and drop** | Drag sections in the layout to manually reorder them. Your custom sort persists per user. |
| **Manage Views panel** | Provides per-user sort toggles and the ability to toggle visibility without deleting them. |
| **Admin default order** | Project owners and admins can define a default order for newly created boards globally. |

<Aside type="tip">
Per-section counts, visibility toggles, and manual sorting persist server-side for each user, so different team members can organize the same board in the way that makes most sense for their workflow.
</Aside>

### Moving tasks between sections

There are three ways to move a task to a different section:

1. **Drag and drop** — in the web UI, drag a task card from one column to another.
2. **MCP** — use the `hypertask_section` tool to move a task programmatically:

   ```
   hypertask_section(taskId: 42, sectionId: 5)
   ```

3. **API** — call `hypertask_move_task_between_boards` to move a task to a section on a different board entirely.

## Views

Boards support multiple ways to visualize the same set of tasks. Switch between views without losing any data — they're just different lenses on the same information.

### Board view

The default Kanban layout. Tasks appear as cards organized into section columns. This is ideal for tracking work status at a glance.

### Calendar view

Displays tasks on a calendar based on their due dates. Useful for deadline-driven work where timing matters more than workflow stage.

In the new app shell layout, the calendar toolbar sits on the dark shell background with the date range and navigation chevrons left-aligned next to the sidebar hamburger and back arrow. The week grid renders inside a single grey rounded bordered card, giving the calendar a clean, contained appearance that matches the rest of the shell.

#### Week column header format

Each weekday column displays the day name followed by a task count, for example: **Tue 5 tasks**, **Thu 2 tasks**. The centered day number row has been removed to reduce visual noise — day numbers are now left-aligned inside each column, consistent with the Kanban layout.

#### Real-time updates in Calendar view

The Calendar view updates **live via Pusher**. When a task's due date or schedule is changed — by a teammate, an agent, or a CLI command — the event moves to the new date instantly on every open Calendar view, without a page refresh. This keeps the calendar accurate even when multiple people are adjusting schedules simultaneously.

#### Filtering in Calendar view

The Calendar view supports the same filter set as the Kanban board. You can open the filter modal in two ways:

- **Filter icon** — click the funnel icon in the calendar header (next to the **Today** button). The icon turns blue when any filters are active, so you can tell at a glance whether the calendar is filtered.
- **Keyboard shortcut** — press `<kbd>Shift+F</kbd>` to open the same modal without using the mouse.

Both methods open the same filter panel. You can also filter by tasks you are **following** using the **Following** filter, matching the filter already available on the Kanban board.

### Timeline / Schedule view

A Gantt-style horizontal timeline showing task durations and dependencies. Best for project planning and identifying scheduling conflicts.

### Saved Views

Saved Views let you create reusable filter and sort configurations for a project. Instead of re-applying the same filters every time you open a board, save them as a named view and switch between them instantly.

#### Filters

Narrow down which tasks appear on the board:

| Filter | Description |
|--------|-------------|
| **Section** | Show tasks from specific sections only |
| **Priority** | Filter by Urgent, High, Medium, Low, or None |
| **Assignee** | Show tasks assigned to specific team members |
| **Due date** | Filter by date range or relative periods (overdue, due this week) |
| **Labels** | Filter by one or more labels |
| **Status** | Filter by task status (active, archived) |
| **Creator** | Show tasks created by a specific person |
| **Following** | Show only tasks you are following |

#### Sort options

Control the order tasks appear within each section:

- **Manual** — custom drag-and-drop ordering
- **Priority** — highest priority first
- **Due Date** — earliest deadline first
- **Size** — smallest estimate first
- **Created At** — newest or oldest first
- **Updated At** — most recently changed first

#### Subtask display

Control how subtasks appear on the board:

| Mode | Behavior |
|------|----------|
| **None** | Subtasks are hidden from the board |
| **Parent** | Subtasks are grouped under their parent task |
| **Flattened** | Subtasks appear as individual cards alongside regular tasks |
| **Card** | Subtasks display as nested cards within the parent |

<Aside>
Saved Views are per-project. Each team member can create their own views without affecting others.
</Aside>

#### Sharing a view via deep link

Every Saved View has a shareable URL that encodes the project and view name. When a team member opens the link, the board switches to that view immediately — no manual navigation required.

The URL format is:

```
https://app.hypertask.ai/project?id=<project-id>&view=<view-slug>
```

For example, a view named **Bugs** in project `15` would share as:

```
https://app.hypertask.ai/project?id=15&view=bugs
```

Copy the URL from your browser's address bar while the view is active, or share it directly from the view picker. Using the browser **Back** button after following a deep link returns you to your previous location without disrupting the view selection.

#### Reordering views

You can customize the order of your views in the **Manage Views** panel:

- **Drag and drop** — click and drag view tabs to reorder them. Your custom sort persists server-side, so the order applies across all your devices.
- **Per-user sort** — different team members can drag and pin their preferred top views.
- **Admin default order** — project owners and admins can define a default order for views. Newly created boards use this centralized arrangement, while existing boards keep each user's custom order.
- **Visibility toggle** — hide views without deleting them (hidden views are restored when tasks are added).
- **Reset** — quickly restore the default view order for boards with centralized settings.

When you hover over a view tab, a gear icon 🛠️ appears in the header, revealing quick access to view options: visibility, pinned status, edit, and delete.

### View counts

Each view displays a count of active tasks (Normal status) and archived tasks separately:

- The total count shows all non-archived tasks in the view.
- Hidden views that contain no items appear dimmed in the views list. When they subsequently receive tasks, they automatically reappear in their previous position as a normal view with a task count.
- Views that are hidden because they contain a zero count will display "0 tasks" but remain visible (dimmed) until tasks are added.

<Aside type="tip">
For frequent users, per-user sorting lets you prioritize the views you use most often, while admins can maintain a predictable organization for new users.
</Aside>

#### Quick view-tabs pill bar

You can switch between saved views without opening the Manage Views panel. At the top of the board surface is a pill bar that exposes a selection of your 8 most-used views. Click a pill to instantly switch the board to that view — the URL updates (for example, `<code>?view=bugs</code>`) and the board content loads accordingly. This provides one-click access to your preferred views for day-to-day work.

#### View tabs

In Manage Views, each saved view appears as a tab. Like other tabs, switching to a view tab also updates the URL with its `<code>?view=</code>` parameter. This keeps your desired view fresh and lets you easily return to it later using the URL alone or by clicking the pill again. Changes to view order (including per-user drag resor or admin defaults) apply to both the Manage Views panel and the quick-pill bar.
