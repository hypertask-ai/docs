Every project in Hypertask has a **board** — a visual workspace where tasks flow through customizable columns called **sections**. If you've used Kanban boards before, this will feel familiar. If you haven't, think of it as a whiteboard with columns that represent stages of work.

## Guest boards

- Anonymously visit an empty guest board for the app.hypertask.ai host (hypertask.ai in production).
- Enter the guest board directly from the root URL logged out (no redirect hop) ([HTPR-4845](https://app.hypertask.ai/detail/project-15/4845)). The guest board is seeded once and persists until you log in or sign up.
- The cookie consent banner and "Log in" and "Sign up" buttons appear in the header for logged-out visitors ([HTPR-4883](https://app.hypertask.ai/detail/project-15/4883)).

## Authentication

Hypertask supports multiple authentication methods, all integrated through the server-side session layer:

### Email-based authentication

- Sign-in with a six-digit code delivered via email
- Access a persistent sign-in link (doesn't expire until used)
- No need to manage custom tokens — the session is handled server-side
- Reliable across mail scanners and email clients

### Sign-out

All authentication flows support clean sign-out that immediately invalidates the session and clears cookies.

### Cookie consent and guest CTAs

- Cookie consent banner appears on guest boards to capture consent for analytics and personalization (opt-out and edgy).
- Header includes "Log in" or "Sign up" depending on session state under the board title, with links to app.hypertask.ai app pages ([HTPR-4883](https://app.hypertask.ai/detail/project-15/4883)).

## Free tier limits

Free users (no active paid or team plan) are limited to a maximum of **3 owned boards**. This limit applies across all board-creation surfaces:

- App web interface
- CLI (`ht --create-board` / `ht board create`)
- MCP tool (`boards.create`)
- Manifest-based board creation
- AI chat prompts that create boards

When a free user reaches the board limit, the creation surfaces block board generation and prompt them to upgrade to a paid or team plan. On the web UI, this appears as an in-app toast with upgrade options.

**Example:**

```bash
# This succeeds for free users with fewer than 3 boards
ht --create-board marketing-campaign-2026

# This fails when the limit has been reached
ht --create-board secret-project
# > Error: Board limit reached. Upgrade to add more boards.
```

## Project pages safety

Secure and reliable project page navigation is critical for boards. Hypertask ensures `/project` page loads correctly by:

```text
GET /project?{boardId|*|<shareId|?>}
────────────────────────────────────────
200 OK (no crash; no NEXT_REDIRECT body injected in buffers)
```

- Valid board IDs blend into the URL so the correct board opens directly.
- Minimizing redirects and avoiding middleware that rewrites responses reduces round-trips.
- Bad or unexpected parameters are handled gracefully, preserving a clean UI rather than crashing or exposing errors in the rendered payload.
