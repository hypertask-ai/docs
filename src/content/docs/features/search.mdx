# Search

Search across your board to find tasks fast. Type to filter by people, boards, labels, statuses, dates, and more, with autocomplete that suggests operators and values as you type.

## Search filters

Use operators to filter tasks by specific fields:

- **from:** Restrict to tasks created by a specific person.
- **assignee:** Restrict to tasks assigned to a specific person.
- **in:** Restrict to tasks in a board, section, or column.
- **label:** Restrict to tasks with a specific label.
  - **Board-scoped label suggestions (Owner + QA preview):**
    - When a board is picked with an `in:` or `board:` chip, `label:` only suggests labels from that board.
    - Each label shows the number of search results on the right (open and done, not archived).
    - Labels with zero results appear at the bottom, greyed out.
    - Without a board selected, all your labels appear (same-name labels merged into one row).
  - <div class="asideInfo"><small>Preview for owners and QA only. Behind the `<flag:htpr-6878-search-label-scope>` flag.</small></div>
- **is:** Narrow by type; for example, `is:card` to show only standard cards.
- **dates:** Show tasks matching a date condition.
  - `dates:2026-10-03` Tasks with this exact due date.
  - `dates:<2026-10-03` Tasks due before.
  - `dates:>2026-10-03` Tasks due after.
  - `dates:in-range 2026-10-01..2026-10-07` Tasks within a date range.
  - `dates:overdue` Overdue tasks.
  - `dates:today` Tasks due today.
  - `dates:this-week` Tasks due in the current week.
  - `dates:later` Tasks due beyond the current week.
  - `dates:todays` Tasks due today or yesterday.
- **has:** Show tasks that have a value in a field.
  - `has:due-date` Tasks with a due date.
  - `has:attachment` Tasks with at least one attachment.
  - `has:comment` Tasks with at least one comment.

Combine multiple operators, for example `from:alice label:urgent dates:>2026-10-03` to find urgent tasks created by Alice after a specific date.

## Autocomplete

As you type, Hypertask suggests:

- **Filter names**: Type `la`, `fr`, or `is` to reveal `label:`, `from:`, and `is:` with ghost text. Press <kbd>Tab</kbd> or <kbd>Enter</kbd> to accept.
- **Filter values**: After typing `from:` or `label:`, a dropdown shows people or labels. After typing `is:`, a dropdown shows states like `open`, `done`, and `archived`.
  - `has:` shows `attachment`, `comment`, and `due-date` options.
  - `dates:` shows presets: `today`, `this-week`, `last 7 days`, plus a date picker.
- **Filter types have unique colours**: People (blue), boards (green), labels (amber), status (violet), dates (coral).

## Person name matching behavior ([HTPR-6881](https://app.hypertask.ai/detail/project-15/6881))

**Owner and QA preview:**

- **Typed person filters**: When you type a name for `from:`, `assignee:`, and currently `commenter:`, it matches every person you can see whose name or email contains that text, ignoring case and accents. For example, `from:valentin` finds Valentin Yeo and any account named valentinyeo; `assignee:yc` finds Yusuf C. and any name containing "yc" in the email. Using `-from:valentin` excludes all those matches.
- **People from the picker**: A person you select from the autocomplete list is matched exactly, so `from: Valentin Yeo` narrows to just that person.
- **Without the flag**: If the `<flag:htpr-6881-search-fuzzy-person>` is off, typed person filters require the exact full name and case-sensitive search.

## Tips panel

When the search bar is empty or focused, a <strong>tips panel</strong> lists every operator with an example and plain meaning. Click any tip to insert it. Saved searches and recent searches also appear inside the tips panel.

## Keyboard navigation in search

- **Navigate suggestions**: Use ↓ (or <kbd>j</kbd>) and ↑ (or <kbd>k</kbd>) to move through values and tips without typing.
  - In empty search, <kbd>j</kbd>/<kbd>k</kbd> moves through tips.
  - In a typed query, <kbd>j</kbd>/<kbd>k</kbd> move through results while you type.
- **Accept a suggestion**: <kbd>Tab</kbd> or <kbd>Enter</kbd> inserts the pending value.
- **Escape**: Closes suggestions and drops focus from the search bar.
  - On search results, <kbd>Esc</kbd> returns you to your previous search term and its results, or to recent searches and tips when there is no previous search.
  - Esc never leaves you on a blank results page.
- **Open a result**: Put focus on a result row with arrows, then press <kbd>Enter</kbd> to open the task.

## Results while typing

Results appear while you type via debounced search. No need to press <kbd>Enter</kbd> to see matching tasks.

## Chips

After applying filters, clickable chips appear in the search bar. Click a chip's X to remove it. Clearing text keeps filter chips until you press <kbd>Backspace</kbd> one extra time.

**Board chips** now display the board icon and name (e.g., `board:inne`), with no extra `#` prefix.

When you type a filter operator such as `from:` or `assignee:` and select a person from the dropdown, the operator character is now absorbed into the chip itself. For example, selecting a person after typing `from valentin` results in a `from: Valentin Yeo` chip instead of leaving `from` and the person both visible.

**Board tabs behavior**: When the board-tab flags are enabled and all search results come from the same board, either because you filtered to one board or because results naturally returned from a single board, the row of board tabs is hidden to keep your attention focused on that board. If the search returns tasks from multiple boards, the tabs remain visible so you can switch between them from search results.

## People and board pickers

- **@ people picker**: Start typing `@` to select or create people.
- **# board picker**: Start typing `#` to select or create boards.

Pickers appear when typing a people or board-related operator such as `from:`, `assignee:`, or `in:`.

## New tasks appear immediately in search

<Aside type="tip">

Tasks created through the API now appear in search results right away without needing to update their title.

</Aside>

Previously, when you created tickets via the API without a title update, the search index would not reflect the new entries. Now, Hypertask updates the search index immediately after task creation, so the new tasks show up when you search.

To verify it’s live:

- Create a new task using the API or CLI with just a description.
- Switch to the search screen and use a keyword from the description to see the new task appear in results.
- No additional steps like editing the title are required.

This change applies to all API surfaces, including the MCP tools and REST endpoints, and makes search results consistent across all task creation flows. ([HTPR-7131](https://app.hypertask.ai/detail/project-15/7131))
