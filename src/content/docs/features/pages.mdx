Pages keep research and notes on your boards. A page can stand alone or link tickets. Open **Pages** below **Table** in the sidebar. You can also use **Commands → Go to Pages**.

## What is a Page?

A page belongs to a board. Linking a ticket does not grant access. Pages follow their board’s existing permissions. Pages are:

- **Board-owned:** Stand alone or link multiple tickets.
- **Markdown-first:** Write in markdown; the editor renders rich HTML with TipTap.
- **Agent-friendly:** Created, appended, updated, and archived programmatically via CLI, MCP, REST, and AI Chat.
- **RAG-indexed:** Every write is indexed so the AI can search, summarize, and reason over page content.
- **Versioned:** Every change is captured with history and restore capabilities.
- **Conflict-safe:** Optimistic-lock guards return a 409 conflict if multiple agents try to write at once.

## Create and find pages

1. Open **Pages** from the sidebar or Commands.
2. Choose **This board** or **All boards**.
3. Search by page title or content.
4. Choose **New page** to start a document.
5. Choose its board when prompted.

Your title and content save automatically.
**Archived pages** lists documents removed from active lists.

## Search finds a page from different words

<span class="label label--brand">Improvement</span> Pages were already sent to the search index, but page search only matched the exact words you typed. Page search now reads that index, the same way ticket search does, so a page written as "view tab count includes cards in hidden columns" is found by "tab counter includes cards that the view hides".

What changed for you:

- **The Pages screen** returns the right page for a question written in your own words, up to 50 results per search.
- **Agents** get the same behaviour through the page search tool in REST, MCP and AI Chat.
- **Exact words still work**, and exact matches stay first in the list.
- **Board access is unchanged.** A page is only returned when the current page still passes the same board, project, archive and link checks, so better ranking never shows a page you could not open.
- **No search, no change.** The unfiltered page list behaves exactly as before.

The release switch is `htpr-9017-smart-page-search`. With it off, page search falls back to matching the exact words you typed.

## Link tickets and pages

On a page, choose **+ Link ticket**.
Pick an existing ticket from the search window.
**Linked tickets** shows the page’s visible ticket links.
Choose **Unlink** to remove a link.
Unlinking keeps the page and ticket.

On a ticket, open **Commands → Link page**.
Pick an existing page from the list.
The page appears in that ticket’s **Pages**.
Existing page lists also offer **+ Link page**.
Commands also includes **Link page** and **Link ticket**.

Pages without visible tickets show **Back to Pages**.

## Agent permissions for page operations

What an agent may do with pages depends on its access mode:

- **Normal (read/write):** Can create, change, archive, and restore task pages.
- **Read-only:** Can only read pages. Creating, changing, archiving, or restoring is refused.

## Publishing a long report from a file

<span class="label label--brand">New</span> The CLI can read page content from a file, so a long report does not have to fit in one command-line string. Linux caps a single argument near 128KB, which used to force agents to paste a report in pieces.

```bash
hypertask pages create --task HTPR-123 --title "QA report" --html-file report.html
hypertask pages update 456 --content-file report.html --canvas
hypertask pages append 456 --content-file notes.md
```

- `--content-file <path>` reads the content from a file and keeps the page's current type on update and append.
- `--html-file <path>` reads the content and marks the page type `html`.
- Add `--canvas` to store the file exactly as written, styles and inline images included. This is the way to publish a self-contained HTML report.
