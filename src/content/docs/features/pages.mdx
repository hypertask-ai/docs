Full-screen pages for explorations, deep dives, and research attached directly to a task. Pages are markdown-editable, versioned, and automatically indexed for the AI so agents can read, extend, and search them from any surface — CLI, MCP, REST, or AI Chat.

## What is a Page?

Think of a Page as a full-screen notepad for thinking, planning, and research that lives on top of a task. Every page is tied to a specific task, so it stays in context of the work you're on. Pages are:

- **Task-bound:** Live inside a task detail and accessible from the task row.
- **Markdown-first:** Write in markdown; the editor renders rich HTML with TipTap.
- **Agent-friendly:** Created, appended, updated, and archived programmatically via CLI, MCP, REST, and AI Chat.
- **RAG-indexed:** Every write is indexed so the AI can search, summarize, and reason over page content.
- **Versioned:** Every change is captured with history and restore capabilities.
- **Conflict-safe:** Optimistic-lock guards return a 409 conflict if multiple agents try to write at once.

## Agent permissions for page operations

<span class="label label--brand">Security fix</span> Hypertask now properly restricts page actions based on an agent's access mode. Depending on the agent's live configuration, it may be:

- **Normal (read/write):** Can create, change, archive, and restore task pages.
- **Read-only:** Can only read pages. Creating, changing, archiving, or restoring is refused.

**Behavior before this fix:** A read-only agent was able to perform all four page actions (create, change, archive, restore) on task pages, bypassing its access mode and effectively gaining write-like permissions despite being restricted to reading.

**After this fix:** The server checks an agent's access mode before each page action. A read-only agent now receives a secure refusal for all four write operations, and the page remains unchanged.

This change, verified live on the QA team's own board ([HTPR-7155](https://app.hypertask.ai/detail/project-15/7155)), ensures that agent permissions match the documented behavior.

## Comments indexed for search

<span class="label label--brand">Fix</span> Comments that are very long or empty now generate searchable search copies. Previously the AI service that creates these copies would reject such comments, leaving them invisible in results. Now they are compressed and indexed, keeping full search coverage for comment threads. This change is part of the broader Turbopuffer upsert optimization ([HTPR-7212](https://app.hypertask.ai/detail/project-15/7212)), which also affects page content indexing.
