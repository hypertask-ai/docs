# Trusted Domains for Login Security

Hypertask's login security uses Better Auth's trust model to enforce re-authentication before accessing app.hypertask.ai. By default, the trusted domains are expected to include all app.hypertask.ai subdomains (e.g., staging, preview, release Vercel deployments).

## Typical options

Use one of the following strategies in your project's Better Auth trusted domains configuration:

- **Full domains**: Treat every subdomain as distinct. Example: trust app.hypertask.ai, staging.hypertask.ai, preview-hypertaskai-001.vercel.app.

- **Subdomain-only**: Trust any subdomain under app.hypertask.ai, including cross-subdomain flows. Example: trust *.hypertask.ai.

- **Stoplist**: Trust a base domain, then block specific subdomains that should always require re-authentication. Example: trust *.hypertask.ai but stop hypertasks-prod-42ef11-hypertaskai.vercel.app.

Why these choices matter

- Using full domains aligns with the documentation's guidance to not hardcode release names.
- A stoplist for release subdomains prevents leakage across releases (avoiding split-brain) without storing full subdomain lists.

💡 Tip: Make the stoplist explicit in a single place so it’s clear which subdomains should always require re-authentication.
