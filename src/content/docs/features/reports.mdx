The **Reports hub** (`/report`) combines two kinds of reporting:

- **Board analytics** for the board you opened most recently
- Saved reports created by AI chat, agents, CLI, or MCP

The hub shows one live analytics dashboard for the current board instead of a card for every board you can access. Saved reports remain available even when they belong to another board.

## Review board analytics

Open **Reports**, then choose **Board analytics** under **Current board**. The dashboard reads the board's current data each time it loads and refreshes when you return to the browser tab.

Choose a period at the top of the dashboard:

- **Today**
- **Yesterday**
- **Last 7 days**
- **Custom range**, with From and To dates

The dashboard shows:

- Tickets worked on during the period, including tickets that were updated, commented on, moved, or linked to a merged pull request
- The median time to finish a ticket and tickets finished per week
- Finished work and comments by board member
- Created versus finished tickets
- Open and stale tickets by column

Ticket names open the ticket. Merged pull request names open the pull request in a new tab.

<Aside type="note">
If **Current board** is empty, open the board you want to review and return to Reports.
</Aside>

## Review current task counts

When Native Reports is available for your account, the Reports hub lists **Current tasks** under **Current board** for the board you opened most recently. Open it to see the board's current, non-archived tasks grouped by section and assignee.

The report recalculates whenever you load it. A task appears once in its current section. A task with more than one assignee appears once under each assignee, and unassigned tasks have their own row.

The report is responsive and read-only on a phone.

## Open reports from the command palette

From the **Ctrl+K** command palette, use **Go to Reports** to open the hub or **Board analytics report** to open analytics for the active board.

Saved reports are listed separately in the hub. Opening one loads its saved content and board context.

## Agent-authored reports

Agents can author reports by:

1. Using the **Conductor: Create report** tool on a board, with a prompt defining structure and filters.
2. Calling **Report authoring** via CLI (`hypertask report create --agent`).
3. Using MCP `hypertask_report_create` to build programmatic reports.

Report templates often include:

- Board and section selection
- Required pivot fields (status, assignee, due date)
- Optional dimension (size,.priority, tags

Example: hourly team velocity snapshots collected by an agent.

Usage example with the CLI:

```bash
hypertask report create \
  --name "Weekly Velocity" \
  --type velocity \
  --board-id 15 \
  --start "2026-08-01" \
  --end "2026-08-31"
```

The hub loads the report at `/report` with the associated filters.

## Integration with boards

Board analytics always follows one board: the board you opened most recently. Agent-authored reports can still be saved for any board you can access and remain listed in the Reports hub.

Use reports as a basis for:

- Weekly standup summaries
- Release retrospectives
- Resource planning and overcommitment checks

## Status updates

A **status update** is an AI-written summary of what has happened on a board, saved as a report.

**To generate one:** from the board, press <kbd>Ctrl+K</kbd> and run **Generate status update**. It opens when ready.

The update has four parts:

- **Headline** â€” one sentence on where the board stands
- **Shipped** â€” work that reached a done column or was archived
- **In flight** â€” work moving through the other columns
- **Risks and blockers** â€” tickets sitting still or otherwise worth attention

It is written from the same board data the velocity report uses â€” ticket movement over the window, per-column counts, staleness thresholds â€” so the figures it quotes are computed rather than generated. Ticket titles are passed to the model as data, not instructions, so a task title cannot steer what the summary claims.

Each board keeps **one** status update, at a fixed address:

```
/report/<board-slug>/status-update
```

Regenerating rewrites that page rather than creating a new one, so a link to it always shows the current state. The default window is the last 7 days.

<Aside type="caution">
The slug `status-update` is reserved for this feature on every board. A report you create manually with that slug will be overwritten the next time an update is generated.
</Aside>
