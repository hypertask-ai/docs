The **Reports hub** (`/report`) lists saved reports and board velocity reports for boards you can access.

## Review board velocity

Open **Reports**, then choose a board under **Velocity**. You can also open the command palette from a board and choose **Board velocity report**.

Choose **Today**, **7 days**, **14 days**, **30 days**, **3 months**, **6 months**, or **12 months**. The default is **30 days**.

The report shows:

- Median time to finish a task and tasks finished per week
- Finished work and comments by board member
- Created versus finished tasks
- Open and stale tasks by column

## Create a saved report

Ask AI chat or an agent to create a report for a board. You can also save HTML with the CLI or MCP. Saved reports appear under **Reports** in the hub, with their board, author, and last update time.

### CLI

Use a short slug, the board's numeric ID, a title, and an HTML file:

```bash
hypertask report create weekly-summary \
  --project 15 \
  --title "Weekly summary" \
  --html-file ./weekly-summary.html
```

Use `--body` instead of `--html-file` to pass HTML directly. Add `--description` for a short summary. The CLI also supports `report list`, `report get`, `report update`, and `report delete`. Every command needs `--project`; every command except `list` also needs a slug. Deleting a report requires `--confirm`.

### MCP

Call `hypertask_reports` with the `create` action:

```json
{
  "action": "create",
  "input": {
    "project_id": 15,
    "slug": "weekly-summary",
    "title": "Weekly summary",
    "body_html": "<h1>Weekly summary</h1><p>Three tasks completed this week.</p>"
  }
}
```

Use `list`, `get`, `update`, or `delete` to manage saved reports. Open the URL returned by the tool to view the report.

<Aside type="note">
A saved report is a snapshot, not a live query. Include all data in its HTML. Inline styles and scripts work, but network requests and external script libraries do not. Update the report when its data changes.
</Aside>

## Status updates

A **status update** is an AI-written summary of what has happened on a board, saved as a report.

**To generate one:** from the board, press <kbd>Ctrl+K</kbd> and run **Generate status update**. It opens when ready.

The update has four parts:

- **Headline** - one sentence on where the board stands
- **Shipped** - work that reached a done column or was archived
- **In flight** - work moving through the other columns
- **Risks and blockers** - tickets sitting still or otherwise worth attention

It is written from the same board data the velocity report uses - ticket movement over the window, per-column counts, staleness thresholds - so the figures it quotes are computed rather than generated. Ticket titles are passed to the model as data, not instructions, so a task title cannot steer what the summary claims.

Each board keeps **one** status update, at a fixed address:

```
/report/project-<board-id>/status-update
```

Regenerating rewrites that page rather than creating a new one, so a link to it always shows the current state. The default window is the last 7 days.

<Aside type="caution">
The slug `status-update` is reserved for this feature on every board. A report you create manually with that slug will be overwritten the next time an update is generated.
</Aside>

## Best practices

- Give reports clear titles and short slugs.
- Include the reporting period in the content.
- Update an existing report to keep the same link.
- Use inline SVG or CSS for charts.
