## July 7, 2026

**Bug Fixes**

- **Fixed: AI Chat new session, delete chat, and icon now work correctly** — Creating a new chat session (via the icon or <kbd>Ctrl+Shift+O</kbd>) and deleting an existing chat were silently doing nothing. The root cause was that every AI-chat mutation awaited a QStash job scheduled 30 days out, but QStash caps delays at 7 days and rejected every request with a quota error, causing the whole operation to return a 500. The redundant delayed jobs have been removed (a separate sweep already handles chat expiry), so all three chat-session operations — create, update, and delete — now complete successfully. ([HTPR-3902](https://app.hypertask.ai/detail/project-15/3902))

## July 7, 2026

**New Features**

- **ChatGPT can now connect to Hypertask via the OpenAPI adapter** — Hypertask now exposes an OpenAPI schema at `https://mcp.hypertask.ai/openapi.json` that ChatGPT can import as a custom action. This lets ChatGPT create tasks, search tickets, list projects, manage assignees, and more — the same full set of operations available to MCP clients — without requiring native MCP support. Authenticate with the same API key you use for MCP, and any new tool added to the MCP server automatically appears as an available action in ChatGPT. See the [MCP Integration docs](/mcp/overview/) for setup steps. ([HTPR-3635](https://app.hypertask.ai/detail/project-15/3635))

- **Calendar view now has a clickable filter icon** — A funnel icon in the calendar header (next to the **Today** button) opens the filter modal for mouse and mobile users. The icon turns blue when filters are active. The existing <kbd>Shift+F</kbd> keyboard shortcut still works and opens the same modal. ([HTPR-3774](https://app.hypertask.ai/detail/project-15/3774))

**Improvements**

- **CLI 1.3.6: Search results show full titles, links, and cleaner tables** — `hypertask search` now wraps long ticket titles across multiple lines so nothing is truncated, includes a direct link to each task in the results table, and automatically omits empty columns to reduce noise. `--json` is also now listed in `--help` for every command, making it discoverable without consulting the docs. ([HTPR-3875](https://app.hypertask.ai/detail/project-15/3875))

**Bug Fixes**

- **Fixed: Starred task list now matches inbox typography** — Starred task titles were rendering at 16 px on desktop while the inbox, all-tasks, and scheduled lists all use 14 px. The desktop size bump has been removed so Starred is now typographically identical to the other list views: 14 px title at weight 500 and the ticket number at weight 700. ([HTPR-2937](https://app.hypertask.ai/detail/project-15/2937))

- **Fixed: `task get` now returns the full description** — `hypertask task get` (and its `task show` alias) now always prints the complete task description, including long multi-paragraph descriptions that were previously cut off. ([HTPR-3669](https://app.hypertask.ai/detail/project-15/3669))

- **Fixed: Unknown subcommands now fail with a clear error message** — Running an unknown or misspelled subcommand (e.g. `hypertask tasks frobnicate`) previously silently printed the root help page, giving no indication that the command was wrong. The CLI now prints a descriptive error (`'task frobnicate' is not a valid subcommand`) and exits with code `2`, making capability discovery reliable for agents and scripts. ([HTPR-3873](https://app.hypertask.ai/detail/project-15/3873))

**New Features**

- **CLI 1.3.6: `view list` now includes visibility** — `hypertask view list --project <id>` now returns a `VISIBILITY` column alongside each view's ID and title, showing whether a view is `shared` (visible to all project members) or `private` (visible only to you). Useful for agents and scripts that need to distinguish personal views from team-wide ones. ([HTPR-3832](https://app.hypertask.ai/detail/project-15/3832))

- **Fixed: `task create --attach` now reliably uploads and links the file** — Passing `--attach <local-file>` to `hypertask task create` in CLI 1.3.6 uploads the file successfully and attaches it to the newly created ticket with a `files.hypertask.app` URL. Previously the upload could silently fail and no attachment appeared on the task. ([HTPR-3718](https://app.hypertask.ai/detail/project-15/3718))

- **Fixed: `comment add` no longer reports phantom success** — `hypertask comment add` was sometimes returning a fabricated `commentId` while the comment was never actually persisted, meaning `comment list` would not show it. In CLI 1.3.6 the command returns a real comment URL and the comment appears immediately in `comment list`. ([HTPR-3791](https://app.hypertask.ai/detail/project-15/3791))

- **Fixed: `--attach` on `task create` and `comment add` now reliably uploads and links files** — CLI 1.3.6 resolves two attachment issues confirmed in testing: `task create --attach <file>` and `comment add --attach <file>` now both upload the local file and attach it to the task or comment correctly. Previously, the flag existed but the upload could silently fail or the attachment would not appear linked. ([HTPR-3036](https://app.hypertask.ai/detail/project-15/3036), [HTPR-3722](https://app.hypertask.ai/detail/project-15/3722))

- **Fixed: Bare ticket numbers now rejected with a clear error** — Commands like `task update`, `task move`, and `comment list` previously resolved a bare number (e.g. `2992`) to an unintended task, silently acting on the wrong item. The CLI now rejects bare numbers immediately with `Invalid ticket number, expected PREFIX-NNN` (e.g. `HTPR-2992`), preventing accidental edits to the wrong task. ([HTPR-3806](https://app.hypertask.ai/detail/project-15/3806))

- **Fixed: Rich structured descriptions now accepted on `task create`** — Passing a description that uses markdown-style headers, numbered steps, or other structured text (a "bug template" style) was previously rejected by `task create`. Structured descriptions are now accepted and stored correctly. ([HTPR-3671](https://app.hypertask.ai/detail/project-15/3671))

- **Fixed: `comment list` no longer hangs** — In some cases `hypertask comment list` would hang indefinitely waiting for a response. The command now returns instantly and reliably. ([HTPR-3673](https://app.hypertask.ai/detail/project-15/3673))

- **Fixed: Invalid CLI subcommands now exit with code 2** — Running an unrecognised or misspelled subcommand (e.g. `hypertask taks list`) previously exited with code `0`, silently passing in shell scripts that checked `$?`. The CLI now exits with code `2` (the POSIX convention for usage errors), making bad commands reliably detectable in scripts and CI pipelines. ([HTPR-3871](https://app.hypertask.ai/detail/project-15/3871))

**Improvements**

- **CLI v1.3.4: update notifier on every command** — The CLI now checks for newer versions on every invocation and prints a nudge when a newer release is available. This ensures teams running the CLI in scripts or CI stay aware of updates without manually checking. Set `NO_UPDATE_NOTIFIER=1` to suppress the prompt in automated environments. ([HTPR-3871](https://app.hypertask.ai/detail/project-15/3871))

**New Features**

- **CLI & MCP: Access saved views programmatically** — Two new read-only tools let AI agents and scripts work with named board views directly, without scanning every task. `hypertask view list --project <id>` (CLI) / `hypertask_views_list` (MCP) returns all saved views for a project (e.g. "Dev Review & QA", "Tests Running"). `hypertask view get <view-id>` (CLI) / `hypertask_view_get` (MCP) returns the pre-filtered task list for a specific view, with `limit` and `offset` for pagination.
