## July 15, 2026

**New Features**

- **Settings and Calendar sidebars use fixed widths at half-screen viewports** — At 1024px width, the Settings sidebar renders at 480px and Calendar boards and filter sidebars at 384px. This provides consistent, predictable layout behavior and prevents truncation of column names and calendar dates. Verified on production across all major screen sizes. ([HTPR-4155](https://app.hypertask.ai/detail/project-15/4155))
- **Email authentication fully separated from Firebase** — Email-based sign-in no longer uses Firebase Auth; the new flow returns the full cookie set and redirects directly to the user's board. Magic-link and sign-out remain functional. All authentication flows are now server-led, with Firebase retained exclusively for FCM push notifications. ([HTPR-4172](https://app.hypertask.ai/detail/project-15/4172))

**Bug Fixes**

- **Archived view: stable high counts and live across-user updates via useArchivedRealtime + Pusher events** — The archive view now provides stable high counts and returns results at the query boundary with a compound cursor. Archive state from other users reflects live via the `useArchivedRealtime` hook, with changes re-fetched through the existing Pusher INBOX_EVENT / BOARD_EVENT infra. This improves reliability during bulk archival and changes are surfaced instantly across tabs. ([HTPR-4019](https://app.hypertask.ai/detail/project-15/4019))
- **Fixed: AMOLED display for new-comment field** — The new-comment field previously rendered a double border on AMOLED displays. This has been corrected to a single ring. Verified in production's CSS bundle. ([HTPR-4192](https://app.hypertask.ai/detail/project-15/4192))
- **Archived view: hide archived boards by default + optimize for narrow viewports** — The Archive section now defaults to showing only active boards. Archived boards are not displayed unless you explicitly access them via the Ctrl+K command palette. On narrower viewports (<1024px), the Archive section uses the full available width for better readability and interaction. Archived boards remain available when you need to review or restore them, while the default view focuses on current work. ([HTPR-4184](https://app.hypertask.ai/detail/project-15/4184))
- **AMOLED theme: true-black terminal colorscheme** — AMOLED now renders with pure-black backgrounds instead of dark gray. The theme applies terminal-style color palettes to comment inputs, form fields, and interactive surfaces, providing maximum contrast on OLED and AMOLED displays. Activate via Ctrl+K command palette or the theme picker in settings. ([HTPR-4179](https://app.hypertask.ai/detail/project-15/4179))
- **Email login: fixed sign-in flow now provides 6-digit code + reuseable link** — Email authentication now works reliably across scanners and clients by exposing both a sign-in link and a 6-digit code generated from the legacy reusable link+code email. The link does not expire and stays valid until used, addressing issues that prevented mail scanners from delivering emails before expiry and click. Verified on production. ([HTPR-4175](https://app.hypertask.ai/detail/project-15/4175))
- **Better Auth multi-account login: fresh cookies and proper session clearing** — Email login now sets fresh Better Auth, nookies_user, and ht_session cookies for the logging-in user. When switching accounts without logout, the previous user's Better Auth session is properly cleared (Max-Age=0) so the old user's cookies no longer control identity. This resolves cases where switching accounts resulted in seeing the wrong user or a black screen. Verified on production with smoke account testing. ([HTPR-4170](https://app.hypertask.ai/detail/project-15/4170))
- **Inbox: two-name sender column uses ellipsis instead of truncating subject** — On narrow viewports (less than 1024px), inbox rows with two-name sender columns now display an ellipsis (...) to preserve the subject line visibility while still identifying the sender names. Previously, sender names could steal horizontal space and truncate the subject content. Verified live on production. ([HTPR-4169](https://app.hypertask.ai/detail/project-15/4169))
- **Better Auth follow-up: backfill User.emailVerified + tighten account-linking** — User emailVerified fields are now backfilled for verified local accounts, and linking a Google login only works on verified local accounts. This restores strict account-linking behavior, preventing unverified accounts from being orphaned when Google accounts link to them. Verified on production. ([HTPR-4159](https://app.hypertask.ai/detail/project-15/4159))

## July 14, 2026

**New Features**

- **Manage Tags: bulk-select and delete labels** — The Manage Tags panel now supports bulk deletion. Select multiple labels at once using the checkboxes next to each row, or use **Select all** to tick every label in the current search filter. A footer appears showing the count, and **Delete N tags** opens a confirmation modal warning that deletion is permanent before removing all selected labels in one action. See the [Tasks docs](/features/tasks/) for details. ([HTPR-4241](https://app.hypertask.ai/detail/project-15/4241))

- **Beta app layout: left icon rail with splits-style header** — A redesigned app shell is available as an opt-in beta. Press <kbd>Ctrl+K</kbd> and search for **"New layout: left icon rail (beta)"** to toggle it on (default OFF). The new layout replaces the top icon bar with a fixed 48 px left rail: Inbox (with unread badge) and AI Chat on top, board/table/calendar surface switchers in the middle, and avatars, invite, theme toggle, and settings at the bottom. Every surface uses a splits-style header with a home icon for the primary view and inline search/filter controls. It's a pure repositioning of existing icons and actions — no functionality is lost. See the [What is Hypertask? docs](/getting-started/introduction/) for details. ([HTPR-4201](https://app.hypertask.ai/detail/project-15/4201))

- **AI Usage cost-attribution report in Settings** — The **Settings → AI Usage** page now shows a first-party cost-attribution breakdown powered by the AI Gateway's internal metering table (AiUsage). Usage is broken down **By Feature** (AI Chat, Task Writer, Text Enhancement, etc.), **By Model** (Claude Sonnet 5, GPT-5.5, etc.), and **Top Users** — so workspace owners and admins can see exactly where AI spending goes. Access has been widened from owner-only to **owner or admin**. The breakdown degrades gracefully (hidden) if the underlying usage table is unavailable. See the [AI Features docs](/features/ai-features/) for details. ([HTPR-4136](https://app.hypertask.ai/detail/project-15/4136))

- **Drag-reorder board columns and view-tab pills** — You can now reorder board sections and view tabs by clicking and dragging. Dragging sections left or right updates their ranking on the board; dragging view tab pills reorders your views persistently. Both actions persist server-side via `Section.ranking` (for columns) and per-user view order settings (for tabs). The original order is preserved when you revert a drag. Verified end-to-end across reloads and devices. See the [Boards & Sections docs](/features/boards/) for details. ([HTPR-4200](https://app.hypertask.ai/detail/project-15/4200))

- **Manage Views: per-user drag order + admin default order** — The Manage Views panel now lets you reorder views by clicking and dragging. Your custom sort persists server-side, so the order is applied across all your devices and teammates can also pin their preferred views. For projects where you want a consistent start, admins can define a **default view order** for newly created boards. Hidden views retain their task counts (even when zero) and reappear automatically when tasks are added. A "Reset" button restores the default order for boards with centralized settings. See the [Boards & Sections docs](/features/boards/) for details. ([HTPR-4225](https://app.hypertask.ai/detail/project-15/4225))

- **Time tracking: opt-in per board (off by default)** — Time tracking has been decoupled from the board level and is now opt-in per board, starting disabled. Boards with tracking off return an `enabled: false` flag from the Time API and block start tracking requests with a 403 error. To start tracking, enable time tracking from the board or use the Shift shortcut before starting. Shift reverses the state: disable after you're done, and it remains off on next restart. Time reports and history are now powered by server-managed timers across all boards. See the [AI Features docs](/features/ai-features/) for details. ([HTPR-4221](https://app.hypertask.ai/detail/project-15/4221))

- **Manage Views gear on hover** — A gear icon appears in the header of each view tab, revealing quick access to view options (visibility, pinned status, edit, delete) on hover. This gives you faster control over your views without needing to open the full Manage Views panel. ([HTPR-4217](https://app.hypertask.ai/detail/project-15/4217))

- **Manage Views available state** — Child views that are hidden because they contain no items now appear dimmed when displayed in the Manage Views panel. When a view subsequently receives tasks, it automatically reappears in its previous position as a normal view. This makes it easier to spot which views are currently operational versus temporarily hidden. ([HTPR-4224](https://app.hypertask.ai/detail/project-15/4224))

- **Time tracking: per-task timers, running-timers view, CLI/AI control** — Time tracking is now more granular. You can start and stop timers on individual tasks for per-task tracking. A dedicated "Running" board surface (accessed via shortcut <kbd>G-H</kbd>) lists all tasks with active timers. The CLI and AI agents also have control over time tracking, letting you start, stop, and monitor time from the terminal without switching contexts. See the [AI Features docs](/features/ai-features/) for details. ([HTPR-4190](https://app.hypertask.ai/detail/project-15/4190))

- **AI chat: create and delete saved views, edit sent messages** — AI chat can now create and delete saved views, alongside reading and updating them. Sent messages are also editable, giving you the ability to correct typos or adjust context after firing off an urgent response. See the [AI Features docs](/features/ai-features/) for details. ([HTPR-4218](https://app.hypertask.ai/detail/project-15/4218))

- **Theme picker: multiple color modes + Paper theme** — A complete theme picker is now available in app settings, supporting Light, Dark, System, AMOLED, and the new Paper warm editorial light theme. Press <kbd>Ctrl+K</kbd> and search for **"Theme"** or use the prompt picker in Settings to switch themes. The picker is under the account section of the sidebar. ([HTPR-4199](https://app.hypertask.ai/detail/project-15/4199))

- **Onboarding tour replay via Ctrl+K** — You can now replay the onboarding tour at any time using the command palette. Press <kbd>Ctrl+K</kbd>, search for **"Onboarding tour"**, and select the replay option to walk through the new features and interface. This is useful for new users who want a refresher or for teammates who joined after the initial welcome walkthrough. See the [What is Hypertask? docs](/getting-started/introduction/) for details. ([HTPR-4198](https://app.hypertask.ai/detail/project-15/4198))

- **Onboarding v3: question-first AI connect step with live connect confirmation + CLI/MCP/REST tabs** — The onboarding flow now introduces a question-first screen with 6 cards offering different ways to connect. Select an option (CLI, MCP, or REST), and the connection screens now show live status updates as the connection is being established. The CLI tab confirms the connection during `hypertask login`, the MCP tab handles authentication with bearer token fallback, and the REST tab provides a ready-to-paste curl command. Verified end-to-end: question screen → connection with live status → Claude Code successfully connects and can talk to Hypertask. ([HTPR-4167](https://app.hypertask.ai/detail/project-15/4167))

**Improvements**

- **AI Chat: animated thinking dots while waiting for a response** — When you send a message in AI Chat, animated thinking dots now appear immediately in a new assistant bubble, giving you instant visual confirmation that the AI is processing your request. The dots clear automatically as soon as the first token of the response arrives. See the [AI Features docs](/features/ai-features/) for details. Each tag displays a live per-tag ticket count (e.g., "12 tickets · 5 archived"), counting active (Normal-status) and archived tasks separately so you can see how widely each label is used. A filter icon next to each tag applies that label's filter to the board instantly — the command palette closes and the board switches to a filtered view showing all columns with matching tasks. See the [Tasks docs](/features/tasks/) for details. ([HTPR-4177](https://app.hypertask.ai/detail/project-15/4177))

The navigation now completes correctly, so each <kbd>Ctrl+E</kbd> moves the workflow forward through your inbox. Verified on production with real-browser tests. The existing `user_id` path is unaffected. See the [MCP Tools Reference](/api/tools-reference/) for details. ([HTPR-4141](https://app.hypertask.ai/detail/project-15/4141))

- **Fixed: Comment composer overflows when quoting with AI chat open in narrow column** — Previously, when you quoted a comment while the AI panel was open in a narrow column, the composer would stay at a capped small size and the text would overflow upward, making the Send toolbar unreadable. The composer now expands to fit its available width (380px measured) so the comment can be read and posted without scrolling. Blurred composers now scroll smoothly instead of spilling content off the screen. Verified on production with headless click-through testing. - **Fixed: Dia theme: comment edit surface renders stark white** — Comments opened for editing in the Dia theme now render with neutral background colors instead of completely white surfaces, improving contrast and readability across themes. Previously, the board would load but stay on whichever view was last active, requiring a manual switch. Using the browser Back button after following a deep link also works correctly — the board re-arms the view selection rather than silently ignoring the navigation. The tool would match only on `Label.id` (which are UUIDs) and throw a "Label(s) not found" error even for existing tags. The fix allows `setTaskLabels` to accept tag names in addition to IDs, so you can say "add tags [AI, bug]" and the AI will look up the tags by name. Tags are still matched by ID internally for performance, but the name lookup is now added as a fallback. ([HTPR-4202](https://app.hypertask.ai/detail/project-15/4202))

## July 12, 2026

**Bug Fixes**

- **Fixed: AI writer scroll + confirm modal interaction** — The AI Task Writer dialog now scrolls correctly when content exceeds the viewport, and the ESC key properly triggers a confirm dialog instead of negating user intent. When the confirm dialog appears, dismissing it leaves the pending draft in place, and accepting confirms the discard action cleanly. Users can also escape the confirm dialog back to the draft state. Verified on production. ([HTPR-4183](https://app.hypertask.ai/detail/project-15/4183))

- **Sidebar polish: segmented board-sort toggle, manage-favorites gear, remove dead account chevron** — The sidebar board-sort toggle has been simplified to a segmented <kbd>Teams</kbd> | <kbd>Recent</kbd> toggle for easy mouse-based switching below the search bar. A gear icon appears for managing favorites, and the account chevron has been removed to reduce visual clutter. Search now renders as a 14px field on a raised surface with a visible caret. Uses keyboard navigation in favor of a dropdown with the `aria-haspopup` attribute and a 2-level submenu structure. ([HTPR-4180](https://app.hypertask.ai/detail/project-15/4180))

- **Ship view-tabs pill bar: quick view switching without opening Manage Views** — You can switch between saved views without opening the Manage Views panel. At the top of the board surface is a small pill bar that exposes a selection of your 8 most-used views. Clicking a pill instantly switches the board to that view, updating the URL parameter (for example, `<code>?view=bugs</code>`) and refreshing the board content. This provides convenient one-click navigation between your preferred views. Verified live on preview across multiple saved views including Bugs and AI. ([HTPR-4186](https://app.hypertask.ai/detail/project-15/4186))

- **Security: 65 API routes now require valid signed ht_session for nookies_user identity** — Previously, 65 API routes trusted the unsigned `nookies_user` cookie as the authenticated user identity, which enabled account takeover via forged cookies. This has been fixed: all those routes now require a valid, matching signed `ht_session` cookie to validate identity. Verified live on production: forging `nookies_user={"id":6}` now returns 401 instead of 200+ full data, and forging `{"id":1}` for any other user also returns 401. Compatibility: auth, MCP, public, webhook, logged-out, and Bearer-auth routes retain their existing authentication semantics, so integrations and agents continue to work without changes. ([HTPR-4182](https://app.hypertask.ai/detail/project-15/4182))
