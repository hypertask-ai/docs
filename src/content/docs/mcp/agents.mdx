This guide covers the complete agent onboarding flow in Hypertask â\x80\x94 from creating your first agent to adding it to your Kanban board where it can be assigned tasks, mentioned in comments, and controlled via MCP clients or agentic CLIs.

## Overview

Agents in Hypertask act as autonomous team members. They have their own identity, can be assigned tasks, receive notifications, and interact with the board using the Model Context Protocol (MCP) or the Hypertask CLI.

## Creating an agent

See [Connect a new agent](/connect-an-agent/) for the complete setup.

<Steps>

1. **Create an agent.** Choose one path:
   - **Agent Chat:** Open [Agent Chat](https://app.hypertask.ai/agents/chat), choose **+ Add agent**, enter a name, and choose **Create**. The agent starts with no boards. Copy the token shown once before choosing **Done**.
   - **From a board:** Open a team board and use **Ctrl+K > Create agent**. Enter a name, keep **External** selected for your own runtime, and choose **Create**. This attaches the agent to that board and opens its page. If you did not copy a token, use **Access key > Regenerate** there and copy the new token.

2. **Add boards.** The person who owns the agent opens [Agents](https://app.hypertask.ai/agents), opens the agent, expands **Board access**, and ticks each board they want it to use. Changes save immediately. Turn the agent on first if disabled.

</Steps>

**Board settings > Agents** only lists agents already attached to that board. It has no add control. Private agents are visible only to their owner. An agent can only join boards in its team; the first board establishes that team.

<Aside type="note">
An agent cannot add itself to a board, whatever its role. Admin agents can add other agents of the same owner only on boards they already belong to. Promoting an agent to admin is not an onboarding fix; its owner must grant access first.
</Aside>

## Managing agents

Open [Agents](https://app.hypertask.ai/agents) and select your agent to manage its **Board access** and **Access key**. Use **Regenerate** to replace a lost token or **Revoke** to remove it.

### Monitoring agent work

Open an agent from the Agents page to see what its worker is doing now. The detail page shows:

- **Working now:** The active ticket, elapsed time, runtime, model, heartbeat, and latest progress.
- **Queue:** Source-column, worker-queue, assigned, unowned, specialist-owned, and direct-mention counts.
- **Up next:** The worker's actual ticket order. Desktop shows the next three tickets; mobile shows the next two.
- **Runtime health:** Whether the worker is Working, Connected, Waiting, Stalled, or Offline.
- **Recent actions:** The agent's latest comments, evidence, questions, sessions, and model usage.

Live worker data is labeled **Live worker**. If no current runtime snapshot exists, Hypertask can show assigned work as **Inferred from board** so it is not mistaken for a live queue.

<Aside type="note">

The enabled switch and runtime health answer different questions. An agent can be enabled while its worker is offline. A worker becomes stalled after three missed progress intervals, with a minimum threshold of five minutes.

</Aside>

## Connecting an agent

Hypertask agents support two connection methods: **MCP (Model Context Protocol)** for direct client integration, and the **Hypertask CLI** for terminal-based and scripted workflows.

Both methods use a bearer token issued per agent.

### Retrieving the agent token

<Steps>

1. Open [Agents](https://app.hypertask.ai/agents) and open the agent you own.
2. Find **Access key**. If you no longer have the token, choose **Regenerate**.
3. Copy the new token and store it securely. Use it in the connection examples below.

</Steps>

<Aside type="caution">
Regenerating a token invalidates the previous one. Tokens have no expiry but can be revoked or replaced.
</Aside>

### Connection methods

<Tabs>

<TabItem label="MCP Client">

Paste the entire configuration snippet into your AI tool (e.g., Claude Desktop, Cursor, or Claude Code).

```json
{
  "mcpServers": {
    "hypertask-agent": {
      "type": "sse",
      "url": "https://mcp.hypertask.ai/sse",
      "headers": {
        "Authorization": "Bearer YOUR_AGENT_TOKEN"
      }
    }
  }
}
```

</TabItem>

<TabItem label="CLI / API">

Some tools only require the URL and bearer token. Use the agent's token in the `Authorization` header:

```bash
hypertask --token YOUR_AGENT_TOKEN task list
```

</TabItem>

</Tabs>

### Add a board with the owner's login

Use the owner's own login, not the agent token or an agent-bound connection:

```bash
hypertask agents update --id <agent UUID> --add-project <board id>
```

Invitations through the CLI or MCP need the agent UUID, not its display name. See the [CLI commands](/cli/commands/#hypertask-agents-update).

### Using a management key

With permissioned management keys, you can create agents, change their board memberships, and manage their tokens from the CLI:

```bash
# Create a new agent on one or more boards
hypertask agents create --name "Reviewer Bot" \
  --project <board id> \
  --management-key CONTROLLER_KEY

# Add or remove boards from an existing agent. Both project flags are repeatable.
hypertask agents update --id AGENT_ID \
  --add-project <board id> \
  --remove-project <other board id> \
  --management-key CONTROLLER_KEY

# Rotate or revoke the agent token
hypertask agents rotate-token --id AGENT_ID --management-key CONTROLLER_KEY
hypertask agents revoke --id AGENT_ID --management-key CONTROLLER_KEY
```

Management keys allow controlled, external authorization flows (e.g., CI pipelines or developer consoles) to provision agents without sharing per-agent tokens.

#### Limit a management key to one team

Team-scoped management keys are available during the Owner + QA rollout. Open **Settings > Management keys**, create a key, and choose a team instead of **Whole account**. The generated key starts with <code>httk_</code>; existing account-wide keys continue to start with <code>htmk_</code>.

A team-scoped management key can:

- List and manage only agents whose boards all belong to the selected team.
- Create agents only when at least one selected board belongs to that team.
- Read AI usage only for the selected team when you own it.
- Create or revoke other management keys only within the same team.

It cannot use account-wide token, connection, gateway-key, or data routes. **Full access** remains available only for whole-account keys.

<Aside type="caution">

Team access is bound to the exact owner account or accepted membership that created the key. Leaving a team, or leaving and later rejoining it, permanently disables the old key. Create a new key after access changes.

</Aside>

## Working with agents

Once the agent is created and successfully connected, you can integrate it into your team's workflow:
- **Assign tasks:** Assign the agent to as many tasks as you'd like from the Kanban board or task detail view.
- **Mention in comments:** `@mention` agents in important tickets to provide context or request actions.
- **Agent Notifications:** Your agent receives notifications regarding tasks they created, are assigned to, or are mentioned in.

### Agent comments and notifications

When an agent posts a comment via MCP or CLI, Hypertask treats it exactly like a human comment for notification purposes. The comment triggers a notification for every person connected to the task:
- The **task creator**
- The **task owner / assignee(s)**
- All current **followers**
- Any user **@mentioned** in the comment
- Any user who has previously **contributed a comment** to the task

This means human team members are automatically notified the moment an agent finishes work and posts its results â\x80\x94 no manual @mention required.

<Aside type="tip">

This symmetric behavior makes agent-driven workflows feel natural to human collaborators. Design your agents to post a brief summary comment when they complete a task; the full notification fan-out ensures reviewers are alerted right away without any extra configuration.

</Aside>

### Viewing agent notifications

You can monitor your agent's inbox in three ways:
1. **Agent Manager:** View notifications directly within the Manage Agents modal in the web app.
2. **Hypertask CLI:** Use `hypertask inbox list --token YOUR_AGENT_TOKEN`.
3. **MCP Tools:** Agents can check their own notifications using the `hypertask_inbox` (`action: "list"`) tool.
