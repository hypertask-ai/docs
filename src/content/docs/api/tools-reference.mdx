This is the complete reference for all Hypertask MCP tools. Each tool maps to an HTTP API endpoint on `https://mcp.hypertask.ai`. All requests require a `Bearer` token in the `Authorization` header.

<Aside type="note">
All request and response bodies use JSON. Task descriptions and comments now accept Markdown as well as HTML; content_type is optional (HTML and Markdown both render correctly).
</Aside>

## Tasks

### `hypertask_create_task`

Create a new task in a project. This tool supports a `dry_run` body parameter for simulating task creation without persisting it.

**Endpoint:** `POST /api/mcp/tasks/create`

**Body parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `project_id` | number | Yes | Project to create the task in |
| `title` | string | Yes | Task title |
| `description` | string | No | Markdown or HTML description |
| `section_id` | number | No | Place in a specific section |
| `priority` | string | No | `urgent`, `high`, `medium`, `low` |
| `estimate` | number | No | Time estimate (in minutes) |
| `labels` | string[] | No | Array of label names to apply. Creates the label if it doesn't exist on the project. |
| `images` | string[] | No | Array of image URLs to attach |
| `attachments` | string[] | No | Array of file URLs to attach |
| `due_date` | string | No | Due date in ISO 8601 format (e.g. `2025-03-01T00:00:00Z`) |
| `assignee_ids` | number[] | No | Array of user IDs to assign when creating the task. Only user IDs that are members of the project are accepted. |
| `dry_run` | boolean | No | `true` to return a simulation of the task without creating it (`false` to persist; default: `false`) |

**Example request — create and persist a task:**

```bash
curl -s -X POST -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  https://mcp.hypertask.ai/api/mcp/tasks/create \
  -d '{
    "project_id": 15,
    "title": "Add error handling to upload endpoint",
    "description": "Handle invalid file types gracefully.",
    "priority": "high",
    "labels": ["Backend", "Bug"]
  }'
```

**Example response — persisted task:**

```json
{
  "id": 1235,
  "ticket_number": "HYP-43",
  "title": "Add error handling to upload endpoint",
  "priority": "high",
  "section": "Backlog",
  "labels": ["Backend", "Bug"],
  "createdAt": "2025-01-17T10:00:00Z"
}
```

**Example request — dry run (no task created):**

```bash
curl -s -X POST -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  https://mcp.hypertask.ai/api/mcp/tasks/create \
  -d '{
    "project_id": 15,
    "title": "Review PR #1778",
    "description": "**Check for validation issues** before merging:\n- Look for SQL injection\n- Verify endpoints are publicly accessible",
    "priority": "high",
    "labels": ["AI", "Review"],
    "dry_run": true
  }'
```

**Example response — dry run:**

```json
{
  "success": true,
  "validated_task": {
    "title": "Review PR #1778",
    "description": "**Check for validation issues** before merging:\n- Look for SQL injection\n- Verify endpoints are publicly accessible",
    "priority": "high",
    "labels": ["AI", "Review"]
  },
  "warning": "This is a dry run and will not create a task."
}
```

<Aside type="tip">
Use `dry_run: true` to validate input schema, field constraints, and any validation rules before committing changes. Set `dry_run: false` (or omit) to persist the task to the project.
</Aside>

<Aside type="note">
Markdown is accepted for task descriptions. The service renders Markdown for display; raw HTML is rendered as-is when supplied.
</Aside>

<Aside type="note">
Passing valid project member IDs in `assignee_ids` is required when assigning users during task creation. Providing non-member IDs will result in a validation error.
</Aside>

## Task Leases

### `hypertask_task_claim`

Claim an available task for handling using a task lease.

**Endpoint:** `POST /api/mcp/tasks/lease/claim`

**Body parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `ticket_number` | string | Yes | Ticket to claim |
| `owner_id` | string | No | Optional owner identifier (e.g., agent name or ID) |

**Example request:**

```bash
curl -s -X POST -H "Authorization: Bearer $AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  https://mcp.hypertask.ai/api/mcp/tasks/lease/claim \
  -d '{"ticket_number": "HYP-42", "owner_id": "agent-6"}'
```

**Example response:**

```json
{
  "lease_id": "lease-abc123",
  "ticket_number": "HYP-42",
  "claimed_at": "2026-07-29T10:00:00Z",
  "ttl": 600000,
  "owner_id": "agent-6"
}
```

<Aside type="tip">
For best results, include a unique `owner_id` so you can identify which agent claimed the task. You can refresh leases before they expire; the server will return a new lease with an updated TTL.
</Aside>

---

### `hypertask_task_heartbeat`

Broadcast ongoing work by refreshing a task lease.

**Endpoint:** `POST /api/mcp/tasks/lease/heartbeat`

**Body parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `lease_id` | string | Yes | Existing lease ID to refresh |
| `ttl` | number | No | Optional new TTL in milliseconds; if omitted, the server extends the current lease |

**Example request:**

```bash
curl -s -X POST -H "Authorization: Bearer $AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  https://mcp.hypertask.ai/api/mcp/tasks/lease/heartbeat \
  -d '{"lease_id": "lease-abc123"}'
```

**Example response:**

```json
{
  "lease_id": "lease-abc123",
  "refreshed_at": "2026-07-29T10:10:00Z",
  "new_ttl": 600000
}
```

---

### `hypertask_task_release`

Release a claimed task lease so others can pick it up.

**Endpoint:** `POST /api/mcp/tasks/lease/release`

**Body parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `lease_id` | string | Yes | Lease ID to release |

**Example request:**

```bash
curl -s -X POST -H "Authorization: Bearer $AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  https://mcp.hypertask.ai/api/mcp/tasks/lease/release \
  -d '{"lease_id": "lease-abc123"}'
```

**Example response:**

```json
{
  "released": true,
  "lease_id": "lease-abc123",
  "ticket_number": "HYP-42"
}
```

<Aside type="tip">
Always release your lease when done, whether you complete the task or abandon it. This unblocks other agents from claiming it.
</Aside>

## Preparing and retrieving ticket context

### `hypertask_prepare_ticket_context`

Prepare ticket context for AI use while respecting a configured token budget. This helps agents avoid overloading models with information they don't need.

**Endpoint:** `POST /api/mcp/context/prepare`

**Body parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `ticket_number` | string | Yes | Ticket to prepare context for, e.g. `HYP-42`. |
| `token_budget` | number | Yes | Maximum tokens to include in the context. |

**Example request:**

```bash
curl -s -X POST -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  https://mcp.hypertask.ai/api/mcp/context/prepare \
  -d '{
    "ticket_number": "HYP-42",
    "token_budget": 3000
  }'
```

**Example response:**

```json
{
  "ticket_number": "HYP-42",
  "context": "<p>Current ticket: Add error handling to upload endpoint. Description: Return 400 with descriptive error for invalid file types. Status: Backlog. Assigned to: Valentin (valentin@example.com). Due: 2025-03-01T00:00:00Z.</p>",
  "tokens_used": 1240,
  "tokens_remaining_in_budget": 1760,
  "summary": "Full ticket context including description, assignee, status, and due date."
}
```

---

### `hypertask_get_ticket_context`

Get a prepared, token-budgeted context packet for a ticket that can be used directly for AI prompts. This endpoint returns cached, pre-aggregated context when available.

**Endpoint:** `GET /api/mcp/context/pack`

**Path parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `ticket_number` | string | Yes | Ticket to pack context for, e.g. `HYP-42`. |

**Query parameters:**

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `token_budget` | number | No | — | Maximum tokens to include. Inspect the response to see what was used. |

**Example request:**

```bash
curl -s -H "Authorization: Bearer $TOKEN" \
  "https://mcp.hypertask.ai/api/mcp/context/pack?ticket_number=HYP-42&token_budget=3000"
```

**Example response:**

```json
{
  "ticket_number": "HYP-42",
  "context": "<p>Current ticket: Add error handling to upload endpoint. Description: Return 400 with descriptive error for invalid file types. Status: Backlog. Assigned to: Valentin (valentin@example.com). Due: 2025-03-01T00:00:00Z.</p>",
  "tokens_used": 1240,
  "tokens_in_budget": 3000
}
```

### `hypertask_context_pack`

Pull full ticket context in one call with token-budgeted results. This endpoint is intended for AI agents to fetch concise, relevant tickets.

**Endpoint:** `GET /api/context/pack`

**Query parameters:**

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `ticket_number` | string | Yes | — | Ticket ID, e.g. `HYP-42`. |
| `token_budget` | number | No | — | Maximum tokens to include. Inspect the response for tokens_used. |

**Example request:**

```bash
curl -s -H "Authorization: Bearer $TOKEN" \
  "https://mcp.hypertask.ai/api/context/pack?ticket_number=HYP-42&token_budget=3000"
```

**Example response:**

```json
{
  "ticket_number": "HYP-42",
  "context": "<p>Current ticket: Add error handling to upload endpoint. Description: Return 400 with descriptive error for invalid file types. Status: Backlog. Assigned to: Valentin (valentin@example.com). Due: 2025-03-01T00:00:00Z.</p>",
  "tokens_used": 1240,
  "tokens_in_budget": 3000
}
```
