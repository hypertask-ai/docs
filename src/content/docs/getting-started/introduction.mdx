Hypertask is a project management platform built for a world where humans and AI agents work side by side. Instead of treating AI as an afterthought, Hypertask gives agents the same first-class access as human team members â\x80\x94 through the [Model Context Protocol (MCP)](/mcp/overview/) and a full-featured [CLI](/cli/reference/).

The web app lives at [app.hypertask.ai](https://app.hypertask.ai). It's a Next.js application designed for speed, with real-time sync via Server-Sent Events (SSE).

## Why Hypertask?

Most project management tools were designed for humans clicking through UIs. That breaks down when an AI coding agent needs to pick up a task, read context, do the work, and report back. Hypertask solves this.

## How Hypertask is organized

Work in Hypertask follows a simple hierarchy:

```
Team (Organization)
  â\x94\x94â\x80Projects
        â\x94\x94â\x80Sections (columns)
              â\x94\x94â\x80Tasks
                    â\x94\x94â\x80Comments
                    â\x94\x94â\x80Subtasks
                    â\x94\x94â\x80Attachments
```

- **Projects** are containers for related work â\x80\x94 a product, a client engagement, a sprint. Each project has its own board, members, and settings.
- **Sections** are the columns on a project board. Typical setups use Todo, Doing, Review, and Done, but you can customize them however you like.
- **Tasks** are the units of work. They carry a title, HTML description, priority, estimate, assignee, due date, and a unique ticket number like `<code>PROJ-123</code>`.
- **Comments** are threaded discussions on tasks. They support HTML formatting, @mentions, emoji reactions, and file attachments.

<Aside>
Every task gets a sequential ticket number scoped to its project (e.g., `HT-42`). Use these to reference tasks in commits, comments, or conversations with your AI agent.
</Aside>

## Built for async and deep work

Hypertask is opinionated about how teams should work:

- **Async-first.** The inbox, task comments, and auto-summaries keep everyone informed without requiring real-time meetings.
- **Deep work friendly.** No chat. No presence indicators. No "typing..." animations. Communicate through tasks and comments when you're ready.
- **AI agents as team members.** Assign tasks to an AI agent the same way you'd assign them to a colleague. The agent picks up work from its inbox, moves tasks through sections, and posts updates in comments.

## App layout

Hypertask's web app uses a top icon bar for navigation across all surfaces (board, table, calendar, inbox, AI chat). A redesigned **left icon rail** layout is available as a beta opt-in.

### Left icon rail (beta)

Press <kbd>Ctrl+K</kbd> and search for **"New layout: left icon rail (beta)"** to toggle the new layout on or off. It is **off by default**.

The rail is a fixed 48 px-wide column on the left edge of the app:

| Position | Icons |
|----------|-------|
| **Top** | Inbox (with unread badge), AI Chat |
| **Middle** | Board, Table, Calendar â\x80\x94 surface switchers for the current project |
| **Bottom** | Avatars, invite, theme toggle, settings |

Every surface uses a **splits-style header**: a home icon marks the primary view, with search and filter controls inline.

<Aside type="note">
The left icon rail is a pure repositioning of existing icons and actions â\x80\x94 no functionality is lost or changed. The classic top icon bar remains the default experience.
</Aside>

### Themes

Hypertask supports multiple visual themes to match your preferences. Press <kbd>Ctrl+K</kbd> and search for **"Theme"** to open the theme picker. Available themes:

| Theme | Description |
|-------|-------------|
| **System** | Uses your OS default (automatic) |
| **Light** | Clean, bright interface |
| **Dark** | High contrast for low-light environments |
| **AMOLED** | Optimized for OLED displays with true blacks |
| **Paper** | Warm editorial light theme with softer contrast, ideal for reading-heavy workflows |

Themes persist across sessions and are applied globally to your workspace.

## Interfaces at a glance

Hypertask offers three ways to interact programmatically, each suited to different use cases:

| Interface | Best for | Install / setup |
|---|---|---|
| **Web UI** | Daily task management, visual boards | [app.hypertask.ai](https://app.hypertask.ai) |
| **CLI** | Terminal workflows, AI coding agents (Claude Code, etc.), scripts and CI | `npm install -g @hypertask/hypertask_cli` |
| **MCP** | AI assistants (Claude Desktop, Cursor) that need rich tool schemas | See [MCP Integration](/mcp/overview/) |

<Aside type="tip">
**Which interface should I use for AI agents?** CLI commands consume far fewer tokens than MCP tool schemas â\x80\x94 an MCP server injects its full schema into the agent's context window at startup, whereas CLI commands are learned from training data and cost tokens only when executed. For agents with terminal access (like Claude Code), the CLI is the most token-efficient choice. For AI assistants without shell access (like Claude Desktop), MCP is the right fit.
</Aside>
